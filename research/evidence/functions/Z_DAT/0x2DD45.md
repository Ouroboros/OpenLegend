状态：`platform_adapted / converged_no_new_differences`

## 1. 入口与原始字节

- 当前 `Z.DAT` loaded入口为 `0x2DD45..0x2DD77`，50字节、11条指令。
- loaded函数字节SHA256：`9761e098dd4e85e0fac653e44db28a12dc85e5d991ff117d58c5959bd85eafd6`。
- 原始 `Z.DAT` 唯一offset为 `0x27745`，raw函数字节SHA256：`c224a06282aa4d8827a79d7eb8d16b8ac82f16101e9bc83a3e267e989dec8696`。
- loaded/raw只有3个差异字节，全部由DOS加载基址 `+0x20000` 重定位解释，无未覆盖差异。

## 2. 唯一caller与PC合同

完整CodeRefsTo只有 `sub_2C319:0x2C4BF` 一个物理callsite，即jump-table case4。

`0x2C4A4..0x2C4BE`把KDEF `pc+3..pc+1` 三个word执行 `movsx` 后压栈，参数顺序为：

1. expected item ID；
2. true offset；
3. false offset。

返回后 `0x2C4C4` 回收12字节参数栈，`0x2C4C7`先把KDEF PC增加4，再由公共尾部 `0x2C4E9 add ebx,eax`叠加callee返回的有符号offset。机器最终PC因此固定为 `old_pc + 4 + selected_offset`。

## 3. 物品选择槽真值

`word_54B74`是最后确认的物理库存槽号，不是item ID。完整producer复核 `sub_2A86C:0x2A987..0x2A9BF`：

- 页、行、列先映射到可见项；
- 从 `word_D27C0` 取实际库存槽号；
- 用该槽访问双word库存项第一个word，并检查对应物品 `show_introduction == 1`；
- 确认后把同一个实际槽号写入 `word_54B74`。

`sub_2DD45`随后按 `slot * 4` 字节读取该槽当前item ID，与expected ID比较：

- 不等：不写共享状态，返回false offset；
- 相等：先把 `word_54B7A` 写为1，再返回true offset。

它不扫描其他库存槽、不检查count、不在失败时清标志，也不规范化offset。负数或越界slot会执行机器未定义的越界读取。

## 4. 命中标志全局xref

除精确DataRefsTo `word_54B7A` 外，还复核 `0x54B70..0x54B80` 每个地址，排除相邻dword重叠访问：

- `word_54B7A`全程序只有本函数 `0x2DD64` 一处16位写入；
- 本函数外没有精确读取或写入；
- 相邻 `word_54B78` 只有 `sub_2B288` 的两次16位写和一次16位读；
- `0x54B7C`起为 `smp000` 字符串，所有xref均从该字符串地址开始；
- 不存在覆盖 `word_54B7A` 的相邻dword读取。

因此命中标志在当前程序中没有后续可观察读取者。现代实现省略该死写不会改变程序可观察结果。

`89690e50d4231de72f458f6e5c5f1aae8390024b7872323674258ce752ef3e96`

固定域：

## 6. C++ REVIEW与验证

从机器入口单向对照现代链：

- `LegacyGameRuntime::handle_menu_item_result`从用户确认的实际库存slot读取item ID，再传给 `SceneSession`；
- `SceneSession::use_item/prepare_event`把该item ID置入 `EventContext::item_id`；
- case4比较该ID并调用公共 `conditional(value, 4, yes, no)`，得到与机器一致的 `PC + 4 + offset`；
- synthetic script3 `[4,123,0,3,2,200,1,-1]`分别固定item123命中后继续执行opcode2，以及item124失败后直接终止。

现代保存“选择时item ID”，机器保存“slot并在比较时重读item ID”。当前资产所有opcode4均为event_2脚本PC0，比较前无库存变化，二者合法域可观察结果一致；现代还安全拒绝不存在的菜单项和非法库存索引，并省略无读取者的命中死写，故归类 `platform_adapted`。

首轮完整入口、producer、caller、全局xref、KDEF/ALLDEF域到C++复核零新增产品差异，无需修改产品代码或测试。
