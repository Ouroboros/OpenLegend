# Z_DAT:0x2DE03 sub_2DE03

状态：`platform_adapted / converged_no_new_differences`

## 1. 物理边界与二进制身份

- 地址范围：`0x2DE03..0x2DE2C`，共41字节、12条指令。
- IDA加载字节与原始`Z.DAT`文件偏移`0x27803`的41字节完全相同，无重定位差异；两者SHA256均为`eaa12eafb11dd75089bee3d4d81fbc331e646de5f19b50e4804fbcc144a4ffff`。
- 唯一物理caller：`sub_2C319:0x2C511`，即事件解释器opcode6。
- caller依次有符号载入并压入`get_exp=word[PC+4]`、假偏移`word[PC+3]`、真偏移`word[PC+2]`和battle ID `word[PC+1]`；回收16字节后固定执行`PC += 5`及公共`PC += EAX`。

## 2. 汇编独立合同

`sub_2DE03`只执行以下合同：

1. 把第四参数get-exp与第一参数battle ID压栈，调用`sub_31C75(battle_id, get_exp)`；真假偏移不传给battle入口。
2. 返回后严格执行`cmp eax,1`。
3. callee返回值恰为1时返回第二参数真偏移；任何其他值返回第三参数假偏移。
4. caller最终脚本位置为`old_pc + 5 + returned_offset`。wrapper没有独立逃跑分支，也不把非1结果细分。

为解释比较值1的业务含义，本轮限域审计`sub_31C75`的参数入口、最终出口及`word_E6ED2`全部10条xref，但不审计或关闭其完整B8战斗生命周期：

- `sub_31C75`原样保存get-exp和battle ID，结束时有符号读取`word_E6ED2`并返回`word_E6ED2 - 1`。
- `word_E6ED2`在战斗主循环入口写0，终局检测仅写1或2；没有第三个终局写值。
- 终局文字分支证明raw 1选择原文`戰鬥失敗`，raw 2选择原文`戰鬥勝利`；因此`sub_31C75`分别返回0失败、1胜利。
- AI动作11的escape只进入回合内移动/休息路径，不写第三种battle终局值。

## 3. 全资产调用域

独立解析原始`KDEF.IDX/KDEF.GRP`，按`<II4h>`序列化`(script_id, PC, battle_id, true_offset, false_offset, get_exp)`：

- opcode6共145次；完整参数流SHA256：`7558e4efa98b78c11e4d94643b990547801d751976fd76bb8016107a25011779`。
- 首条为`(2,14,0,0,74,1)`，末条为`(1015,686,134,3,0,0)`。
- battle ID范围0..135，共106个不同ID；全部落在`WAR.STA`的140条记录内。
- get-exp只有0和1：0共115次，1共30次。
- 真假偏移全部非负；共19种偏移对，其中`(3,0)`110次，且存在单条两侧均非零的`(8,5)`。
- caller按有符号word传参；现代仅对get-exp转bool。由于完整合法资产域严格为`{0,1}`，该转换无信息损失；现有synthetic值9只用于证明`SceneStepResult`保留原word，不属于原资产调用域。

上述145条统计写入`research/evidence/scene-goldens.json`的`kdef.opcode_6_battle_requests`；当前oracle SHA256为`7c1402a3222149de96630a1e5d39cba0e171fd3de368ea5b52f708f32c3b5062`。

## 4. 单向汇编→C++ REVIEW

机器合同固定后，才对照现代实现：

- `SceneSession` opcode6保存`argument(2/3)`为真假偏移、`argument(4)`为get-exp，先推进PC 5 words，再发出携带`argument(1)` battle ID与原get-exp word的`SceneStepKind::battle`。
- `LegacyGameRuntime::start_battle`用同一battle ID建立`BattleSession`，并以`battle_get_exp != 0`传入经验bool；对原资产0/1严格等价，越界battle ID由现代资源校验稳定拒绝。
- `BattleSession::finished()`排除`stay`；唯一终局赋值把`BattleOutcome::victory/defeat`映射为typed `BattleStepResult::victory/defeat`。
- `finish_battle_if_ready`只把typed victory映射为`SceneResponse::battle_victory`，其余唯一合法终局defeat映射为`battle_defeat`；`SceneSession::resume`仅前者选择真偏移，后者选择假偏移。
- 机器同步调用完整battle后返回offset；现代由runtime异步持有battle会话，结束后再恢复同一解释器。调度方式不同，但合法域的battle ID、get-exp、胜负结果与最终PC一致，归类`platform_adapted`。
- 既有synthetic `(true=0,false=4)`覆盖胜负分支；新增`(true=8,false=5,get_exp=1)`在胜利时到item215、失败时到item214，固定两侧均非零时仍以指令后PC为基址。

首轮完整wrapper、唯一caller、callee结果边界、结果word全部xref、全部145条资产调用和现代恢复链复核未发现产品实现差异；结论为`converged_no_new_differences`。`sub_31C75`及其内部battle函数仍由各自B8/scene-event closure独立终审，不能由本wrapper提前关闭。原程序动态执行继续记录`blocked_runtime_oracle`。
