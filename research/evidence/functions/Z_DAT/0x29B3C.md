## 1. 独立机器恢复

- 函数共 250 bytes、65 条指令、17 个基本块；除编译器栈检查外不调用游戏函数。
- 外层 x 从 0 到 63，内层 y 从 0 到 63，以 `64*y+x` 读取当前场景事件层，严格保持 X-major 扫描；不是遍历固定 200 条事件记录。
- 事件格值恰好为 `-1` 时跳过；否则按 `event*11` 读取事件记录。word5 为动画首图，signed `<=0` 时整条跳过；word6 为末图，word7 为当前显示图，word8 为延迟。
- 对每个有效事件格严格依次执行：word7 `>=` word6 时先将 word7 重置为 word5；若重置后的 word7 `>` word5、`counter%4==0` 且 `<` word6，则按 16 位加 2；若 signed word8 `<=counter%100`、当前 word7 恰好等于 word5 且 `<` word6，则再按 16 位加 2。
- 比较均为 signed；`counter%4` 与 `counter%100` 使用 signed `idiv` 余数。真实 caller 将 counter维持在 `[0,999]`，因此合法运行域余数非负。
- 扫描按事件格执行。同一事件记录若被多个格引用，一次调用会按格出现次数重复读取和写回；合成双格在counter4可把102依次推进到104、106。
- 返回寄存器最终保留最近一次 `counter/100` 或栈检查返回值，但全部caller均不读取该值；可观察职责只有事件word7更新。

## 2. 全部 caller 与 C++ 映射

- 共有两个 caller、五个 callsite：`sub_26B5E` 的scene入口counter0扫描 `0x26E1D` 与主循环预增扫描 `0x26E8F`；`sub_28E40` 的scene入口counter0扫描 `0x28F15`、主循环预增扫描 `0x28F8D`、scene jump counter0扫描 `0x29279`。
- 两个主循环均先执行 `counter=(counter+1)%1000`，再调用本函数，随后才按left→up→down→right等优先级处理输入。入口和scene jump由`sub_296E6`先把counter清零，再在加载精灵后直接调用本函数，不预增。
- 现代映射为 `SceneSession::advance_event_pictures`：`SceneSession`构造和`complete_scene_jump`在counter0直接调用；`idle_tick`先对`animation_counter_`执行`+1 mod1000`再调用。`tick`在处理本tick输入前调用`idle_tick`。
- `event_at`保持X-major坐标读取，`current_picture/end_picture/begin_picture/picture_delay`四个枚举分别承接机器word5/6/7/8；`set_event_field`只写word7。函数返回值无caller语义，现代实现为`void`。

## 3. REVIEW 与平台适配

1. 旧 inventory `research_name=scene_collision_probe` 与实际机器职责不符，本轮修正为 `scene_event_picture_advance`。
2. 从 `0x29B3C` 入口逐指令复核双层循环、四字段signed条件、两次取模、重复事件格副作用、返回尾块和全部五个callsite；现代合法资产域零产品差异。
