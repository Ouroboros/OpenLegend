# 函数证据：`sub_2D590` `0x2D590..0x2D653`

状态：`platform_adapted`

## 物理范围与资源记录

当前 `Z.DAT` 本体范围为 `0x2D590..0x2D653`，共195字节、49条指令。除入口栈边界探测外有9次callee调用；唯一条件分支是共享资源类型 `word_C0BFA == 9` 的IDX缓存门。

缓存未命中时，函数先写 `dword_D5070[0]=0`，再把 `HDGRP.IDX` 的累积结束偏移读到紧邻的 `dword_D5074`。因此head ID `n`的起点是 `dword_D5070[n]`，终点是 `dword_D5074[n]`。函数随后每次打开 `HDGRP.GRP`，按起点seek，读取 `end-start` 字节到共享临时帧缓冲，关闭文件，并调用 `sub_3D8FF(x,y,frame,framebuffer)`。head ID直接作为记录下标，不执行普通legacy sprite ID的除二转换。函数忽略RLE wrapper结果并固定返回1。

IDX打开失败时机器打印内嵌错误字符串、等待按键，随后仍写cache type 9并继续；越界head ID会直接索引全局偏移表。这些非法域不作为可移植正确性合同。

## Caller与合法参数域

完整xref为5个静态callsite、3个owner，且均忽略EAX：

- `sub_22A59:0x22AD7/0x234BF`：角色状态第一页和第二页，从182字节角色记录读取head ID，锚点均为 `(78,68)`；
- `sub_2CC21:0x2CDA0/0x2CE7F`：对话首屏和后续页，style 2/3在调用前跳过，其余style传入对话head ID，锚点为头像框左上角 `(x+2,y+59)`，四个合法位置为 `(25,71)`、`(239,184)`、`(239,71)`、`(25,184)`；
- `sub_3C6D3:0x3C752`：战斗角色状态面板，从参战角色对应记录读取head ID，锚点为 `(242-side_offset,82)`；双方合法值分别为 `(242,82)` 与 `(22,82)`。

当前 `HDGRP.IDX` 为460字节、115个累积结束偏移，末项249,276恰覆盖整个GRP。全部115帧均满足8字节头、逐行长度、run边界、声明宽度与无尾随字节合同；合计7,568个run、226,957个非透明像素。当前RANGER的320个角色head ID范围为0..109，共103种，无越界值；3,561次KDEF opcode1中所有实际绘制style的head ID也均有效，style2/3的无效head参数不会进入本函数。

## 汇编→C++映射与平台边界

`SceneSession`与`BattleRenderer`分别通过 `PackedArchive::open(HDGRP.IDX,HDGRP.GRP)`持有同一资源。两处 `draw_portrait` 均先检查有符号head ID和entry count，再直接读取 `portraits_.entry(head_id)`，经 `SpriteFrameView::parse`后调用 `draw_rle_sprite(framebuffer,frame,x,y)`；不存在legacy sprite除二。

`SceneSession::draw_overlay`覆盖对话两个机器callsite及四个头像锚点；`BattleRenderer::render_character_status`覆盖状态两页并固定 `(78,68)`；`BattleRenderer::render_status_panel`接收 `(242-side_offset,82)` 的typed计划，覆盖战斗状态面板。现有真实对话、角色状态两页和战斗状态面板整帧oracle均包含对应HDGRP像素。

机器以共享type缓存IDX、每次重读GRP；现代在Session/Renderer构造时一次性缓存完整archive。原资产在会话中静态不变，因此合法head ID取得的记录字节一致。现代对负ID、越界ID、损坏IDX/GRP及损坏RLE稳定返回失败，而机器可能越界或继续使用无效缓存；这些属于平台安全适配。本轮未发现合法资源域的产品差异，未修改产品代码或C++测试。

本closure只关闭HDGRP记录定位、head ID直索引、5个caller锚点、帧转发及固定机器返回合同；通用archive格式与RLE逐像素callee语义由其各自resource/render测试负责，不随本行传播关闭。
