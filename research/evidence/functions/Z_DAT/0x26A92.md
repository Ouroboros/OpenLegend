# 函数证据：`sub_26A92` `0x26A92..0x26B5E`

状态：`platform_adapted`

来源：当前 `Z.DAT` 机器码；`research/ida/reports/Z_DAT.b6_world_xrefs.txt`；world及跨scene runtime回归。

## 1. 物理范围与计数门

- 物理范围`0x26A92..0x26B5E`，204 bytes、37条指令、15个基本块；仅横向`sub_23C98`和纵向`sub_23F28`调用，两个caller均忽略返回值。
- 函数入口先递增全局32位计数`dword_54502`。只有递增结果**恰好等于50**才进入队伍循环；其他值直接返回。
- 第50次循环结束后才把计数清0。调用位于方向/移动帧更新、入口探测、碰撞和坐标提交之前，因此移动成功、阻挡、边界夹取和进入scene均计为一次尝试。

## 2. 六槽门禁与原BUG

- 固定扫描slot 0..5。slot0无条件进入属性门；slot1..5仅当队伍role id有符号`>0`时进入，0或负值跳过。
- 伤势从真实队员`roles[role_id].hurt`读取；中毒却从`roles[slot_index].poison`读取。后一索引不是role id，是必须保留的原版错位BUG。
- 两值使用有符号16位严格`>50`的OR门；二者均`<=50`时不修改该队员。
- 命中门后，按HP→MP→physical power固定顺序操作真实`roles[role_id]`；每项仅在有符号16位`>1`时减1，所以2降至1，1、0和负值均不变。
- hurt与poison只用于门禁，不被本函数修改；全链无RNG调用。

## 3. 汇编 → C++ 与平台边界

- `WorldSession::move`在任何方向副作用之前递增`std::int32_t role_recovery_counter_`并严格比较50，随后执行六槽循环和清0；合法会话从0开始且每50次归零，不存在合法路径上的32位溢出。
- `ranger_.roles[role_id].hurt`、`ranger_.roles[index].poison`、OR门、HP/MP/physical power顺序和`>1`下限逐块对应机器指令。
- 同一`WorldSession`在scene同步往返期间继续存活，计数不会因进入或返回scene重置；运行中读档会构造新会话并按原进程初始化语义从0开始。
- 现代实现对slot0负role id及所有越过320条角色表的id执行边界保护；原机将形成表外地址。当前原版资产的slot0和有效队员id均在表内，故该保护不改变合法资产行为，结论归类为`platform_adapted`。
- 本轮从入口按15个基本块重新独立推导并逐块对照，零产品差异、零新增未决项。

## 4. 验证与结论

- world定向回归锁定第49次三属性不变、第50次才触发、hurt=50且slot-poison=50不触发，以及hurt=51时HP 2→1而MP 1和physical power 0保持。
- 错位BUG回归把slot1指向role10，仅令`roles[1].poison=51`，确认衰减写入role10而role10自身poison不参与门禁。
- runtime回归锁定48次普通移动、1次进入scene、保留计数返回world后第50次移动才衰减；scene往返本身不重置或额外递增。
- Linux app Debug：14/14通过，受管进程`proc_be38`。
- B6模块关闭矩阵：Windows core Debug/Release各13/13，Windows app Debug/Release各14/14，受管进程`proc_92e6`。
- 原程序动态差分：`blocked_runtime_oracle`。
