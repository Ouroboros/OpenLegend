# 函数证据：`sub_24F8C` `0x24F8C..0x2558B`

状态：`platform_adapted`

来源：当前 `Z.DAT` 机器码；`research/ida/reports/Z_DAT.b6_world_xrefs.txt`；当前原版五层世界资产。

## 1. 物理边界与扫描域

- 物理范围`0x24F8C..0x2558B`，1535 bytes、344条指令、73个基本块；直接caller为横向世界移动`sub_23C98`、world初始化`sub_24A02`和新游戏scene70返回world尾链`sub_26B5E`。
- 入口先以`sub_3EE90`把sprite、owner-X、owner-Y三个1024-word输出数组各清零2048 bytes，并把条目计数置0。
- 扫描范围严格为X `[view_cache_x-11, view_cache_x+21)`外层、Y `[view_cache_y-11, view_cache_y+21)`内层，共32×32格；每个X列独立把向上回扫下界初始化为`view_cache_y-11`。
- 候选条件是BUILDX或BUILDY任一非0、当前玩家cache格、或船current相对cache origin的格；不以`in_ship`门控船节点。

## 2. 玩家、船与建筑条目

- 同一格同时匹配时玩家分支优先于船分支。玩家条目写world X/Y和sprite标记5000，并把该坐标暂写目标owner格；船条目次优先，写船current world X/Y、标记6000并暂写owner格。
- 普通格从条目0开始线性找首个相同owner X/Y。未找到时以owner world坐标减cache origin索引BUILDING owner格，把其sprite id和owner pair追加。
- 所有建筑sprite id按unsigned16检查`<=0x2064`；负word同样因unsigned比较失败。四个错误点分别覆盖保存尾项、搬移项、插回项和新追加项，机器打印`error 0..3`并等待退出。
- 扫描结束把16位条目数写`word_54506`。三个caller均只依赖重建后的数组，后续调用覆盖EAX，不把本函数清理尾部的偶然返回值作为业务状态。

## 3. 重复owner重排

- 找到重复owner时不追加。若命中项已是列表尾项，直接结束该格；否则保存当前尾项并从当前Y-1向该列回扫下界递减扫描。
- 对每个非空且既不同于当前格owner、也不同于命中项owner的上方格，把`[found,last)`整体后移一位，再把保存的原尾项写到`found`位置；机器不提前break，多次满足时会重复旋转。
- 完成非尾重复处理后把该列回扫下界设为`current_y+1`。现代`scan_floor_y`、反向扫描、逐项后移和保存尾项写回保持相同顺序。

## 4. 汇编 → C++ 与适配

- `render::build_legacy_world_depth_list`复制128×128 owner层，在副本注入typed玩家/船节点，再按同一X/Y扫描、首项查找、重复旋转及owner格sprite读取生成`LegacyDepthEntry`。
- DOS版直接暂写原owner cache，结束后按unsigned `<128`分别清玩家、船current、船next格；现代只修改副本，因此无需恢复，单次及后续合法原资产重建不留下注入值。
- 现代显式拒绝不足128×128的层、越出cache的32×32视口和越cache的owner坐标；机器依赖caller和原资产保证这些前置条件。原错误打印/等待改为typed error并由world render记录日志，属于平台适配。
- 从入口重新逐块核对三个清零、双循环、候选门、玩家/船优先级、首项去重、非尾旋转、四处ID门和三个清理坐标，零新增产品差异。
