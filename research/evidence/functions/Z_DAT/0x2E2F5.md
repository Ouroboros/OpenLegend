# 函数证据：`sub_2E2F5` `0x2E2F5..0x2E337`

状态：`assembly_exact`
最终REVIEW：`converged_no_new_differences`

## 1. 物理边界与调用者

- 入口/出口：`0x2E2F5..0x2E337`，66字节，22条指令。
- loaded bytes SHA256为`4558ac4d5836ca13bd20fd042834b3555bcf550eb84a6062fd93e01ba0d9daf6`；原始`Z.DAT`文件偏移`0x27CF5`起66字节SHA256为`91a65940ab92f424e14810ac5ccf3ffc31df8955e45e6f1b1b813e03666854ca`。
- 唯一字节差异在函数offset25，属于背包首槽item ID地址从raw `0x0006FE2C`重定位为loaded `0x0008FE2C`（恰加`0x20000`）；归一化后无差异。
- 唯一物理caller为`sub_2C319:0x2C65F` opcode18。caller按右到左压入假偏移、真偏移、目标item ID，使用helper返回值，并在共享路径把PC推进固定4 words后叠加signed offset。

## 2. 入口到出口机器行为

helper令匹配标志=0、索引=0，然后扫描200个背包记录的item ID word：

1. 记录步长为4字节；只读取每槽第一个signed item ID word。
2. item ID等于参数时置匹配标志1，并令索引=200；循环尾自增后退出，因此首个匹配即停止。
3. 不读取同槽count，不要求count为正，也不汇总重复ID。
4. 扫完未命中时标志保持0。
5. 标志为1返回第二参数真偏移，否则返回第三参数假偏移。

因此count为0或负值的槽只要ID匹配仍算“拥有”；空槽ID `-1`仅在目标本身也是`-1`时匹配。函数不修改背包。

## 3. 当前原资产域

独立Python按68槽真实宽度扫描全部1,018条KDEF，opcode18仅2次：

- `(script37,PC0,item173,true0,false15)`。
- `(script38,PC0,item173,true0,false20)`。
- 完整`<IIhhh:script_id,pc,item,true,false>`参数流SHA256为`3f25065164137f7c2ec64615393422cc449b804fa50db0183a5ed188bd19ab6f`。
- PC公式固定为`old_pc + 4 + selected_signed_offset`；两组目标均由全局条件门证明落在同记录合法指令边界。

真实script37回归固定：slot0=`(item173,count0)`仍选真并结束为stay；完全无item173时选假进入对话139；仅slot199=`(item173,count-32768)`仍选真，证明扫描包含末槽且数量完全不参与判断。
