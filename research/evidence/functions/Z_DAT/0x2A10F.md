## 2. 独立机器合同

1. 参数filter以完整32-bit保存在ESI；实际caller只传0和4。
2. `sub_3EE90(EAX=0xD27C0, ECX=400, EDX=0xFFFFFFFF)`先把200个signed-word输出槽全部填为`-1`。
3. EDX作为库存slot，严格按0..199升序扫描。机器以`slot*4`读取signed item ID；数量word完全不读。
4. signed item ID为负时跳过；非负时按190-byte stride读取signed item type。机器不做ID上界检查。
5. 接受条件严格为`type == filter || filter == 0 || (type == 3 && filter == 4)`。
6. 接受时写入原库存slot，不是item ID或逻辑网格index；结果保持slot顺序，重复item ID分别保留，count0或负count仍可收录。
7. 未写尾部保留`-1`；若200项全收录，结果恰为`0..199`，不保证存在sentinel。
8. EBX在退出前恢复，EAX依末项路径变化，不定义业务返回；两个caller均忽略或覆盖EAX。

## 3. 首轮现代差异与最小修正

首轮读取现代实现后发现三处同源合法域差异：`LegacyGameRuntime::update_menu_counts`遇首个负ID即截断而未扫描后续槽；`GameMenuController`只保存数量并把逻辑网格index直接当库存slot返回；`BasicUiRenderer::render_items`同样按连续逻辑index读取且遇空槽停止。中间空槽后的有效库存因此会被漏画或映射到错误物品。

最小修正令`GameMenuController`持有固定200项signed-word slot映射，输入时先填`-1`再复制稳定前缀；`selected_inventory_slot()`把逻辑位置映射回真实库存slot。runtime改为扫描全部200槽、忽略quantity并收集合法非负ID的原slot；renderer仅消费该映射读取/高亮。既有`set_inventory_count`保留identity映射兼容。现代对`item_id >= 200`安全跳过，替代机器越界读取，归类`platform_adapted`。

`BattleSetup::begin_item_selection`首轮即精确实现filter4的type3/type4并集、全200槽扫描、`-1`预填、signed值、数量无关和原slot稳定输出，无产品修正。
