# 函数证据：`sub_2422A` `0x2422A..0x24278`

状态：`platform_adapted`

来源：当前 `Z.DAT` 机器码；`research/ida/reports/Z_DAT.b6_world_xrefs.txt`。

## 1. 物理范围与调用边界

- 物理范围为`0x2422A..0x24278`，78 bytes、14条指令、5个基本块；唯一直接caller是纵向移动入口`sub_23F28`。
- caller有两个调用点：陆地步行成功或下船成功汇合到`0x240BF`后调用，以及乘船水域成功的`0x24119`分支调用。登船命中由另一分支直接从船主坐标恢复Y，不调用本函数。
- 唯一被调函数是Watcom栈检查`sub_3ED1E`；本函数不读取X、不判碰撞、不消费RNG、不加载资源，也不写RANGER header。

## 2. 独立机器恢复

- 入口以参数`4`调用栈检查，随后读取唯一32位参数并直接加到32位world Y。
- 加法后先按32位有符号数检查`<0`，命中则写0；再按32位有符号数检查`>479`，命中则写479。两个限制块次序固定。
- 最后以32位减法计算`world_y - cache_origin_y`，把结果写入cache-local Y全局并保留在`EAX`返回。
- 唯一caller只传`-1/+1`，且只在碰撞成功后调用；合法可达坐标域不会触发32位溢出。caller不消费返回寄存器，随后才执行axis=1的cache提交。

## 3. 汇编 → C++ 映射

- `WorldSession::complete_move`在非登船的成功分支按`world_y_ + delta_y`并限制到`0..479`，承接陆地步行、乘船水域和下船三类调用路径。
- 现代不持久保存cache-local Y，而由`cache_y()`实时返回`world_y_ - cache_.origin_y()`。`reload_cache_if_needed(true)`在提交前读取旧origin下的local阈值，必要时重载origin；重载后再次读取`cache_y()`即得到机器后续cache提交更新后的local值。
- 逐指令对照栈检查、32位加法、两个有符号限制、local减法、两处caller和返回值消费，未发现需要修改产品实现的差异。

## 4. 平台适配

- DOS可写全局dword改由`WorldSession`坐标与`WorldCache` origin持有；cache-local Y从冗余状态改为按需派生，避免两份宿主状态失同步。
- 机器返回local Y但caller不读取，现代因此没有独立返回接口；无效会话门禁由更外层移动入口承担。

## 5. 验证与结论

- 四方向连续移动固定cache-local Y为`[64,63,63,64]`，直接覆盖向上提交、横移保持Y和向下提交。
- 合成纵向scene continuation从Y=100恢复后提交到101，cache origin Y=36且`cache_y()==65`；继续向下到Y=135后重载origin=71，local Y回到64。
- 原资产乘船从Y=172向下提交到173时，cache origin Y=108且`cache_y()==65`。
- Linux app Debug：14/14通过，受管进程`proc_f782`。
- 原程序动态差分：`blocked_runtime_oracle`。
