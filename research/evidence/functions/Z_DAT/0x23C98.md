# 函数证据：`sub_23C98` `0x23C98..0x23F28`

状态：`platform_adapted`

来源：当前 `Z.DAT` 机器码；`research/ida/reports/Z_DAT.b6_world_xrefs.txt`。

## 1. 物理范围与调用边界

- 物理范围为`0x23C98..0x23F28`，656 bytes、167条指令、39个基本块；唯一直接caller是world主循环`sub_20D35`。
- 主循环按左、上、下、右优先级只处理一个方向；本入口只接收横向`-1/+1`。调用返回后统一进入待处理I/O、天气、待机动画和render/present尾链。
- 本入口调用移动消耗、场景入口、登船、步行阻挡、船体双格、下船、X坐标提交、cache提交、天气滚动和深度重建；唯一caller不使用返回寄存器。

## 2. 独立机器恢复

- 入口以参数`32`调用Watcom栈检查，保存`EBX/ESI`，把唯一参数保存在`ESI`；随后无条件先调用`sub_26A92`移动尝试消耗。
- 陆地分支只清idle-active `word_544F8`与20-tick计数`word_544F6`。它不清50-tick计数`word_544FA`、idle step `word_544FC`或四拍delay `word_544FE`。walk offset按16位加2，有符号严格`>12`时回到2；负向方向为2、非负向为1，当前帧写方向base加offset。
- 乘船分支不写陆地idle字段；ship offset按16位加2，有符号严格`>6`时回到2，方向同样为负向2、非负向1，并写船帧。
- 候选X按32位`current_x + delta`计算并限制到`0..479`。任何碰撞判定前先以`(candidate_x,current_y)`调用`sub_25911`；场景同步返回后保留候选和delta，从同一入口后半段继续。
- 场景返回后的当前`in_ship`为0时，先以方向1/2和候选坐标调用`sub_24496`。命中船主格或下一格时，helper置乘船、重置船帧、把命中目标改为船主格并按方向设置另一格；caller从该船主X恢复world X并进入提交。
- 未登船时调用`sub_24667(candidate_x,local_x,local_y)`；严格返回1才调用`sub_241DC(delta)`提交X，否则坐标不动。
- 当前`in_ship`非0时，`sub_24559`检查的两格严格是“候选目标格”和“沿同一delta再前一格”，不是“当前位置”和“候选格”。水域探测返回1时提交X，再把船主格设为新world坐标、另一格设为其`±1`。
- 船体水域探测失败后以方向1/2调用`sub_246F9`下船探测；返回1时切回陆地并提交X。仍失败时world坐标不动，但船主格改为当前位置，另一格改为当前位置`±1`。
- 所有成功分支依次调用`sub_24278(0)`提交/cache重载，并仅在weather-active严格等于1时调用`sub_24417(0,delta)`滚动天气。成功、阻挡和登船/下船全部最终调用`sub_24F8C`重建深度列表。

## 3. 汇编 → C++ REVIEW 与修正

- `WorldSession::move`承担移动消耗、动画、候选限制与场景入口；`WorldMoveContinuation{direction,target_x,target_y}`保存机器在`sub_25911`同步调用期间留在寄存器中的后半段状态。
- `resume_move_after_scene -> complete_move`在返回侧present/fade后恢复碰撞、坐标/cache提交与天气滚动，不重复移动消耗或动画；保留的`WorldSession`继续使用原cache、天气、idle、50次移动计数和palette。
- 首轮对照发现陆地移动错误清零50-tick计数、idle step和delay，却没有清机器实际写0的20-tick计数。最小修正只清`idle_animation_`与`idle_counter_`，保留中断时的step/counter/delay。
- 同轮发现船体水域探测错误读取“当前格+目标格”。最小修正把delta传入私有helper，严格改为机器的“目标格+前方第二格”；旧回归中一格过晚的下船预期同步改为机器边界。
- 两处修正后从`0x23C98`入口重新逐基本块对照移动消耗、陆地/船动画、场景continuation、四类碰撞、阻挡出口、船双格、cache/天气和深度重建，未发现新增差异。

## 4. 平台适配

- DOS全局word/dword、并行层缓存和立即深度表改由`WorldSession`对象、`WorldCache`与render时即时深度列表承接；阻挡路径无需持久重建一份随后才消费的宿主列表。
- 原机器方向来自唯一caller的`-1/+1`，现代接口使用受约束枚举；无效会话安全返回。`in_ship`仍保留16位非零分支语义，weather-active在合法可达域映射为bool。
- 原机器直接更新会话全局；现代按保存/切换边界由`sync_persistent_state`回写RANGER header，不改变运行中移动结果。

## 5. 验证与结论

- 回归在idle step 8时以向右移动中断动画，确认移动后前20个idle tick仍为walk offset 2、第21个恢复方向base，下一次idle激活从step 10继续而非从2重启。
