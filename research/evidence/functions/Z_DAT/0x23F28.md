# 函数证据：`sub_23F28` `0x23F28..0x241DC`

状态：`platform_adapted`

来源：当前 `Z.DAT` 机器码；`research/ida/reports/Z_DAT.b6_world_xrefs.txt`。

## 1. 物理范围与调用边界

- 主体物理范围为`0x23F28..0x241DC`，692 bytes、166条指令、45个基本块；唯一直接caller是world主循环`sub_20D35`。
- 主循环按左、上、下、右优先级只处理一个方向；本入口只接收纵向`-1/+1`。负向由up输入传入，正向由down输入传入。
- 所有主体出口都反向跳到横移入口末尾共享块`0x23F20..0x23F28`；该块调用`sub_24F8C`重建深度列表，再恢复本入口保存的`ESI/EBX`并返回。完整入口到出口审计包含该共享尾块。

## 2. 独立机器恢复

- 入口以参数`32`调用Watcom栈检查，保存`EBX/ESI`并把delta保存在`ESI`；随后无条件先调用`sub_26A92`移动尝试消耗。
- 陆地分支只清idle-active与20-tick计数，不清50-tick计数、idle step和四拍delay。walk offset按16位加2，有符号严格`>12`时回到2；负向方向写0，非负向写3，当前帧写方向base加offset。
- 乘船分支不写陆地idle字段；ship offset按16位加2，有符号严格`>6`时回到2，负向方向写0、非负向写3并更新船帧。
- 候选Y按32位`current_y + delta`计算并限制到`0..479`。任何碰撞判定前先以`(current_x,candidate_y)`调用`sub_25911`；场景同步返回后从同一后半段继续。
- 场景返回后的当前`in_ship`为0时，方向0/3调用`sub_24496`。登船命中后helper把命中目标设为船主格并按方向设置纵向另一格；caller从船主Y恢复world Y、限制到`0..479`并更新cache-local Y。
- 未登船时调用`sub_24667(candidate_y,local_x,local_y)`；严格返回1才调用`sub_2422A(delta)`提交Y，否则直接进入共享深度重建尾块。
- 当前`in_ship`非0时，`sub_24559`严格检查“候选目标格”和“沿同一delta再前一格”；两格X相同，Y分别为`candidate_y`与`candidate_y + delta`。水域返回1时提交Y，并把船主格设为新world坐标、另一格设为Y `±1`。
- 水域失败后以方向0/3调用`sub_246F9`下船探测；返回1时切回陆地并提交Y。仍失败时world不动，但船主格改为当前位置，另一格改为当前位置Y `±1`。
- 所有成功分支依次调用`sub_24278(1)`执行纵向cache提交，并仅在weather-active严格等于1时调用`sub_24417(1,delta)`按纵轴滚动天气；随后与所有阻挡分支一起进入共享深度重建尾块。

## 3. 汇编 → C++ 映射

- `WorldSession::move`按`WorldDirection::up/down`产生`delta_y=-1/+1`，承担移动消耗、动画、候选限制与场景入口；typed `WorldMoveContinuation`保留候选Y和方向。
- `resume_move_after_scene -> complete_move`恢复纵向碰撞后半段，不重复移动消耗或动画。`delta_y != 0`严格选择纵向坐标提交、`reload_cache_if_needed(true)`和天气`(+18*delta_y,-9*delta_y)`公式。
- 前一横移入口终审已修正这两个入口共享的陆地idle清态和船体“目标格+前方第二格”采样。本轮从`0x23F28`入口重新逐基本块检查修正后的共享实现，方向0/3、Y参数次序、场景continuation、登船/船行/下船/阻挡、纵向cache与天气顺序均无新增差异。

## 4. 平台适配

- DOS全局word/dword、并行层缓存和跨函数共享退栈尾块改由`WorldSession`对象、结构化返回与C++作用域承接；render时即时构造深度列表，等价替代每次移动出口的持久重建。
- 唯一caller只传`-1/+1`，现代使用受约束方向枚举；无效会话安全返回。原裸16位方向和数组索引在合法原资产域内保持一致。
- 场景异步宿主阶段保留原`WorldSession`，在返回侧present/fade后恢复同一continuation，再进入天气、待机动画和render尾链。
