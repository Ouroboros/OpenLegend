## 普通IDX路径

index filename前四byte并非严格lowercase `mmap`时：

1. 调用`sub_3CF45(index_filename,index_table+start_index)`读取完整IDX，并取得signed 32-bit文件长度。
2. 通过`SAR/SHL/SBB/SAR`按4除并向0截断得到`N`；正值等于`floor(size/4)`，callee失败返回`-1`时得到0，尾部余数byte被忽略。
3. 令`d=N-1`；只在signed `d>0`时逆序写`pointer[start+d]=group_destination+index[start+d-1]`，地址、下标和加法均是32-bit机器运算。
4. 无条件写`pointer[start]=group_destination`。
5. 随后无条件调用`sub_3CF45(group_filename,group_destination)`，其返回长度原样通过唯一RET返回。

owner不验证IDX非空、4-byte对齐、累计offset单调/范围、目标pool容量、地址回绕、GRP长度或I/O短读。

## `mmap*`专用路径

只比较index filename的前四byte，依次严格等于lowercase `m,m,a,p`即进入专用路径；第五byte及后续内容不参与判断。

机器先构造`global_prefix+filename`，但先打开bare filename，失败后才打开prefixed filename。两次open均为`-1`时打印`no this file '%s'....\n`并调用`sub_3EE5F(1)`；该CFG块无successor。成功时执行seek调用，固定向`index_table[start]`读取`0x3A4C=14,924` bytes，忽略read结果并关闭handle，然后无条件令`N=0xE93=3,731`。pointer构造及GRP读取与普通路径相同。

原始`MMAP.IDX`为34,924 bytes/8,731 dwords；前14,924 bytes为3,731个单调累计offset，最后值`1,572,545`恰等于`MMAP.GRP`长度；后20,000 bytes为5,000个零dword。机器仅消费有效前缀。完整MMAP IDX/GRP SHA256=`7d50e9ae0ca9df0bb4d2bb361b83562973f6495af8f537ea8d6d2d5574ac0e6d`/`8793acc6761f5ca73e89c0fa21a5f9cac3483ac0fa5864cda3a5549ae2d98594`，有效前缀SHA256=`5eac5f4a43516e1f730dbb5d75509a9fe6a5613c2d2c098b5fee7044bd84ccf1`。

## sentinel与末帧

SDX/WDX走普通路径，其IDX最后dword为0。该zero本身不作为pointer offset；因为机器使用`index[start+d-1]`，倒数第二个累计offset成为最后entry的起点，而最后entry读到对应SMP/WMP EOF。现代`SentinelArchive`以前N-1个累计offset生成raw ranges，再显式追加`[last_end,group_size)`；`BattleRenderer`的WDX offset vector实现同一规则。

重复累计offset只会让raw range长度为0，不会让机器得到透明帧。若`index[k-1]==index[k]`，则`pointer[start+k]`与`pointer[start+k+1]`相同，两个legacy index共享从该地址到下一严格更大pointer（或group EOF）的RLE。当前`SDX058`中`index[2826]=index[2827]=330629`、`index[2828]=333129`；legacy id `5654/2=2827`与`5656/2=2828`均取得`SMP058[330629,333129)`。独立parser确认该2500-byte RLE为`94×134`、offset `(7,140)`、2002个非透明像素，SHA256=`1e33f240e37115cf136c61a17588d6fa0a79b33895c940d70e3d0e2c5cbdd4d7`；两ID在独立`320×200` framebuffer上同anchor绘制均得SHA256=`ae2524138a8ac91baf972aad793bab95f1ebb02f8ca9e84fc683d06df8c752b2`。

独立只读资产oracle覆盖118对普通IDX/GRP及84对SDX/SMP、26对WDX/WMP：普通有效项18,193且均非空；110对sentinel共428,105项，其中65,087项raw range非空。全量重复offset审计另固定SDX 4,539段、298,757个raw空alias位、最长额外alias链1,329，WDX 679段、64,191个raw空alias位、最长额外alias链1,399；全部累计offset、EOF、原始byte SHA256均固定在聚合合同SHA256=`aa0f40cd18a01593961962f7523e07461a1915175fbd539e9ec751c187fc0250`。

## 共享恢复尾

`0x3D82A..0x3D832`是8-byte/6-instruction恢复尾：`add esp,8; pop ebp; pop edi; pop esi; pop ebx; ret`，SHA256=`0cfb2e0a0993b64c1ee1cf56512945a1a18c729cdb952faebd43f795f45de6be`。本owner从GRP读取fall-through进入；`sub_3D950`的`0x3D9AB`与`0x3DA3B`另有两处外部jump进入，分别预置EAX=0和EAX=ESI。两个外部入口不执行archive逻辑，保持`sub_3D950` owner独立，本行closure不传播。
