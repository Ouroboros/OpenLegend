## 2. 参数、路径和打开优先级

- cdecl参数固定为`arg_0=filename pointer`与`arg_4=destination pointer`；没有destination capacity参数。
- `sub_3ED1E(0x1C)`后保存EBX/ESI。`sub_3E33D()`返回后，无条件执行`sub_3EF4A(unk_E6EEC,"%s%s",byte_1187BC,filename)`，把全局前缀与原文件名拼入共享fallback缓冲；即使第一次open成功，该写入也已发生。
- 先调用`sub_3EFB9(filename,0x200)`；仅返回32-bit `-1`时才调用`sub_3EFB9(formatted_fallback,0x200)`。因此路径优先级严格为caller给定字符串，其次全局前缀拼接结果。
- 机器用固定全局字符串缓冲且无格式化容量参数；超长/无NUL文件名没有稳定安全合同。

## 3. 双打开失败与Q门

- 两次open都为`-1`时，使用原始`filename`调用错误打印，格式固定为`no this file '%s'....\n`。
- 紧循环调用`sub_20C32`并只比较AX，严格等待`0x0051`即uppercase Q；其他返回继续等待。
- Q后没有return或exit，EBX仍为`-1`并直接落入公共长度/seek/read/close链；最终返回长度helper的原样结果。缺失文件上的具体DOS错误码由被调I/O helper决定，本owner不修正。

## 4. 成功读取链与返回值

公共链严格为：

```text
ESI = sub_3F6CA(handle)
sub_3F728(handle, 0, 0)
sub_3F544(handle, destination, ESI)
sub_3F64D(handle)
return ESI
```

- 首个调用取得32-bit文件长度；随后定位到0，只发出一次恰ESI bytes的读取请求并关闭。
- seek、read和close返回值全部丢弃；成功路径返回长度查询值，不是实际读取计数。
- owner不分块、不重试、不检查负长度或destination容量。合法caller必须提供足够缓冲并依赖底层一次读满。
- 空文件长度0，公共链仍执行0-byte请求并返回0。
