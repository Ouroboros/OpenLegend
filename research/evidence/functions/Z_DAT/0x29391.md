# 函数证据：`sub_29391` `0x29391..0x294AD`

状态：`platform_adapted`

来源：当前 `Z.DAT` 机器码、独立 IDAT 批处理输出、原始 DOS 场景档案、`research/tools/generate_b7_scene_goldens.py`、持久化与场景回归。

## 1. 物理身份与控制流

- 装载范围 `0x29391..0x294AD`，284 bytes、66条指令；原文件范围 `Z.DAT[0x22D91:0x22EAD]`。
- 原文件 SHA256：`0a9e903317b3a47b529e2ce0a2f7fc38f6adae44661a6f568a4ac2320f20abbc`。
- 装载函数 SHA256：`61dc1c778dc57f70bd0fad4723406d252ffc6bf0c9c0e4c61f36e56331fbb5f9`。
- 18项绝对地址重定位全部为 `raw + 0x20000`，逐项归一化后装载字节与原文件字节一致。
- 三个直接caller分别为新游戏scene70初始化、普通场景入口和内部场景跳转；调用点为 `0x26D8D`、`0x28E8C`、`0x291F9`。
- 函数末尾不是本地 `ret`：事件档案读取后跳到共享尾 `0x295C2..0x295D0`。该尾块14 bytes，SHA256 `ebe39eaf5fad2b9dd012622ca937bf6d848a262b66cf239ef16b4d65840e3ab6`，顺序为清理读调用参数、关闭事件GRP句柄、恢复寄存器并返回。

## 2. 地图档案读取

机器先检查共享IDX cache tag是否为2。不是2时清偏移表，打开 `ALLSIN.IDX` 并解析偏移；打开失败打印原字符串 `allsin.idx not found` 后进入原机终止链，成功后把cache tag设为2。

随后每次调用都以模式 `0x202` 打开 `ALLSINBK.GRP`，以scene id索引解析后的起始偏移，执行绝对seek，从该位置读取固定 `0xC000`（49,152）bytes到当前场景地图缓冲，随后立即关闭地图GRP句柄。

## 3. 事件档案读取

地图读取后检查同一共享IDX cache tag是否为3。由于地图段刚把它设为2，合法调用会重新打开并解析 `ALLDEF.IDX`；失败时打印原字符串 `alldef.idx not found` 后进入终止链，成功后把cache tag设为3。

随后以模式 `0x202` 打开 `ALLDEFBK.GRP`，按同一scene id寻址，读取固定 `0x1130`（4,400）bytes到当前场景事件缓冲，再跳入共享关闭尾完成句柄关闭与返回。场景地图与事件记录因此严格成对，顺序固定为map后event。

## 4. 原始资产与独立oracle

当前两份基准IDX与工作IDX逐字节相等：`ALLSIN.IDX/ALLSINBK.IDX` SHA256均为 `6d35d9c9b233cd389261d58ca2f17d4f12f6dba1f429ac8ff6217ce3b10ab94a`，`ALLDEF.IDX/ALLDEFBK.IDX` SHA256均为 `99ad387b0ec7790ea684e3d9edf4777b35273703108b1c2ba0d584ddffc51c20`。

`ALLSINBK.GRP` 为100×49,152 bytes，SHA256 `830ae313ccabe310a16d330eac83647a9c81a6c23efce6069ca87dc653f0e154`；`ALLDEFBK.GRP` 为100×4,400 bytes，SHA256 `3633122f6a43f0b5dd390c2fa2516766d735a064ca955c8766b73232230a4480`。独立生成器确认两份工作GRP等于按基准IDX解析后拼接的100条记录，并固定scene 0、70、99的独立记录哈希。

## 5. 汇编 → C++ 单向对照

现代实现不在每次 `SceneSession` 切换时重新打开两份GRP，而是在 `persistence::load_baseline_scenes/load_snapshot` 边界一次性验证并导入100条固定场景地图/事件记录；`GameSnapshot::scene_maps/scene_events` 保留原始字节布局和固定累计末端，`SceneSession`按scene id读取对应原始跨度。外部场景修改直接写同一内存快照，运行中读档则整体替换快照，所以机器“写工作GRP后下次进入重读”的合法可观察结果保持一致。

逐项对照结果：

- scene id到记录偏移的映射与固定记录尺寸一致；
- map先于event可用，场景会话只在完整快照验证成功后创建；
- 新游戏、普通入口、内部跳转三种caller均消费同一快照内容；
- 原机显式句柄关闭由现代RAII和全档案所有权取代，不保留跨帧文件句柄；
- 原机缺IDX时打印并终止，现代在会话创建前返回结构化加载错误并由runtime显示错误，属于平台错误处理适配；
- 非法scene id的机器越界读取未定义，现代稳定拒绝，属于平台保护。

合法当前资产路径零新增行为差异，本项无需修改产品C++。

## 6. Closure与结论

独立generator已两次从原始 `Z.DAT`、IDX和工作GRP生成完整golden并逐字节比较一致；正式 `scene-goldens.json` SHA256为 `383b72bbdd38a73d91cf939f7057e191838bc2e6266aec4fb8bce80a119e24bd`。机器审计同时覆盖三个caller、18项重定位和共享关闭尾；持久化回归覆盖scene 0/99边界值、严格记录尺寸、无效IDX布局/GRP尺寸拒绝、快照往返与场景修改隔离。
