# 函数证据：`sub_36FF9` `0x36FF9..0x37070`

状态：`platform_adapted`

映射：`openlegend::battle::BattlePathing::initialize(BattlePathMode::targeting)`。

## 机器身份、入口与owner边界

- 独立临时IDB导出完整`119` bytes、`39`条指令、`10`个跳转、`4`处32位重定位和`1`次direct call。
- 原文件偏移`0x309F9`；raw SHA256为`bd2a44e6f71689d02b361c3ce4efdff3d14927ab43b509e9c2bfd4cb6ae67e0d`，加载重定位后SHA256为`c36d21be447066b7fd6ba9c2b113e67a63c965cac16c285363eb1316405c1b4b`。全部4处fixup位于相对偏移`0x20,0x4C,0x56,0x61`，加载值均比原文件大`0x20000`，逐处逆变换后完整119字节与只读`Z.DAT`一致。
- 唯一入口xref为`0x36E89`，归属targeting wrapper `sub_36E7F`；唯一direct call为`0x36FFE -> sub_3ED1E`，负责8-byte栈探测。直接RNG消费为0。
- 本函数以自有`pop ebx; ret`退出，不进入`0x39A3E`共享尾。本owner只关闭targeting阻挡图初始化；caller `sub_36E7F`和后续`sub_37070` flood step保持独立owner。

## 完整机器合同

1. `0x37004..0x3702B`先以外层EBX、内层EDX遍历64×64 path word，把全部4096格写0；索引为EBX×64+EDX。
2. `0x3702D..0x3706C`再以外层EBX=x、内层EDX=y遍历64×64，按signed `y*64+x`定位upper layer和path word。
3. `0x37042..0x37057`只检查upper layer word：恰等于0时写254，任一其他16位值（含负值）写555。
4. 本函数不读取occupancy，也不读取ground layer或九段tile区间。
5. 两轮循环均比较16位DX/BX是否小于64，但计数从0开始且仅执行64次，不发生回绕。第一轮为y外/x内，最终扫描为x外/y内。
6. 最后一格的byte offset为`2*(63*64+63)=8190`；最终store、循环收尾和`pop ebx; ret`均保持EAX，因此正常返回8190。
7. 唯一caller在`0x36E8E`立即以`movsx edx, word_556D8`开始source索引计算，未读取返回EAX，故现代void接口等价。
8. source强制归零、255槽队列和`sub_37070` flood step均属于caller `sub_36E7F`的独立owner合同。

## 汇编到现代实现逐块对照

- `BattleData::battlefield()`后4096 words对应机器upper layer。
- `BattlePathing::initialize(targeting)`对每格只执行`upper_layer != 0 ? kBattlePathBlocked : kBattlePathUnvisited`后continue；不读取occupancy和ground，判定及555/254写值完全一致。
- 现代单次线性遍历等价于y外/x内，机器最终遍历为x外/y内。各格只依赖同index upper只读输入，函数体无回调、RNG或中途出口，因此最终4096-word结果一致，写序差异不可观察。
- 现代省略机器第一轮全图写0。机器在预清零与最终覆盖之间无外部调用或读取，且第二轮必定覆盖全部4096格，因此省略的中间态不可观察。
- 现代void本地返回替代机器EAX=8190；唯一caller忽略EAX，行为一致。
- 首轮完整入口REVIEW覆盖全部39条指令、10个跳转和RET出口，零产品差异。省略预清零、改变独立格扫描顺序及void返回登记为平台适配。
