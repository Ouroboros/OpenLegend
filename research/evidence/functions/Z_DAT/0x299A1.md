# 函数证据：`sub_299A1` `0x299A1..0x29B3C`

状态：`platform_adapted`

来源：当前 `Z.DAT` 机器码；`research/ida/reports/Z_DAT.b7_scene_xrefs.txt`；独立 B7 oracle。

## 1. 独立机器恢复

- 函数共 411 bytes、90 条指令、29 个基本块，唯一显式参数为 signed step。
- 入口将 idle active `word_544F8` 与 20-tick `word_544F6` 清零，但保留 50-tick `word_544FA`、idle step `word_544FC` 和 delay `word_544FE`；随后步行动画 offset 加 2，大于 12 时回到 2。机器在 `0x299D9` 对 step 执行 `test`/`js`：`step < 0` 写 direction 0（up），否则写 direction 3（down）。阻挡也不回滚这些副作用。
- 目标 y 为 `current_y + step`，随后裁剪至闭区间 `[0,63]`；x 保持不变。
- 按机器短路顺序检查：target building 必须为 0；signed `target_height-current_height < 10`；target event 为空，或其 `cannot_walk` 为 0；target earth 不得落入九个闭区间 `[358,362]`、`[374,380]`、`[458,464]`、`[506,610]`、`[818,824]`、`[838,838]`、`[934,936]`、`[1016,1022]`、`[1324,1348]`。
- 任一门禁失败即保留原 y 和 view origin；全部通过才提交 y，并将 view origin y 按 `y-11` 裁剪至 `[0,36]`。本函数不改 x 或 view origin x。
- 坐标在边界时仍先选择方向并推进步行动画；裁剪后的同格只要可行走，仍执行成功提交路径。

## 2. 全部 caller 与 C++ 映射

- 共有三个 caller、六个 callsite：`sub_26B5E` 新游戏 scene 主循环 `0x26EE5`；`sub_28E40` world 进入 scene 后的主循环 `0x28FE3`；`sub_2F171` opcode 30 脚本步行的四个象限分支 `0x2F221/0x2F26C/0x2F2B7/0x2F2FF`。所有 callsite 只传 `+1/-1`。
- 键盘 caller 对 up 传 `-1`、down 传 `+1`。opcode 30 以目标和源 y 的比较选择 step；例如 script343 从 `(28,24)` 到 `(28,19)` 的五步均传 `-1`。
- `SceneSession::move` 对应键盘 caller；`apply_scripted_walk_step(false, step)` 对应 opcode 30。共享 `target_is_walkable`、`update_view_origin`、`player_frame` 与 `commit_header`承接机器的碰撞、视口、图号和全局状态提交。
- 现代实现对非法 scene/event 索引、损坏资产和 pending 状态进行边界保护；这些机器未定义域保护归平台适配，合法资产与全部真实 caller 域按汇编顺序一致。

## 3. 差异修正与整轮重启

1. 旧证据把 `test`/`js` 方向分支反读为“负 step 朝下”，并据此让 `apply_scripted_walk_step` 对垂直 step 使用反向枚举；旧独立 oracle 和 script343 单测又固化了同一错误。
2. 本轮以机器指令和 `sub_2F171` 实参重新交叉确认：y 减小时 step 为 `-1`，必须写 direction 0（up）。修正产品实现及独立 oracle 后废弃旧结论，从 `0x299A1` 入口重新逐块复核。
3. 继续检查共享 idle 字段 xref，又发现现代 `cancel_player_idle_animation` 未清机器要求的 20-tick，反而清了机器移动时保留的 50-tick、idle step 和 delay。再次废弃结论，将 helper 收窄为只清 active 与 20-tick。
4. 修正后 script343 的五帧为 picture `5004/5006/5008/5010/5012`，frame FNV-1a64 依次为 `b53215ff283c375a`、`a6cae4420f245b6e`、`3f2f76d31c813bf3`、`e1d227f227ef9d0e`、`f2a1e35490a4f647`；结束基础图为 `5002`。阻挡路径仍推进同一五帧并保持实际 y。
5. 从入口重审状态清理、符号方向、目标裁剪、四级碰撞短路、成功/阻挡尾块、view origin 和全部六个 callsite，修正后零新增差异。

## 4. 验证与结论

- 合成回归隔离 building、signed 高度差 10、event `cannot_walk`、九个 earth 闭区间双端点，并覆盖 y=0 向上、y=63 向下的同格裁剪及视口端点。
- 20 个 idle tick 后移动、再执行一个 idle tick仍保留walk帧，证明移动清零20-tick；50 个 idle tick 后执行最短 opcode 30，脚本结束后的下一 idle tick立即消费一次RNG，证明50-tick未被移动清零。
- script343 正常和 building 阻挡路径均断言 direction up、五个图号与正常路径逐帧 framebuffer hash；scene70 四向真实资产向量继续通过。
