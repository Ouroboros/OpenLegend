# 函数证据：`sub_22A59` `0x22A59..0x2399E`

状态：`platform_adapted`

## 机器合同

当前 `Z.DAT` 的函数入口接收角色编号，并连续显示两页角色状态。每一页开始时按 `word_C0BF2` 重画调用方背景：世界调用 `sub_2558B`，场景调用 `sub_29D2D`，战斗调用 `sub_3AA85`；随后绘制圆角面板 `(55,0,210,200)`、HDGRP 头像 `(78,68)` 和按姓名首个 NUL 计算横坐标的角色名。第一页 present 后调用 `sub_20C32` 等待任意非零键，第二页重新执行同一背景与面板入口；第二页 present 后再次等待任意非零键并把 last-key 清零后返回。

第一页显示等级、生命/上限、内力/上限、体力/100、当前经验、升级阈值，以及攻击、防御、轻功、医疗、用毒、解毒、拳掌、御剑、耍刀、特殊兵器和暗器。当前生命按内伤 `0 / 1..33 / 34..66 / >66` 分色，最大生命按中毒 `0 / 1..49 / >=50` 分色；内力类型 `0/1/2` 使用三组固定色，其他值沿用此前由中毒分支留下的颜色。攻击、防御、轻功分别累加两件编号非负装备的对应有符号加成。等级有符号值 `>=30` 时显示固定等号，否则从 30 项无符号阈值表显示升级经验。

第二页显示两件编号非负装备的次名称、编号非负修炼物的次名称、当前修炼经验、所需修炼经验或满级等号，以及最多十项编号非负的已学武功。武功熟练度以无符号 16 位读取，显示 `熟练度 / 100 + 1`。修炼物无关联武功时分母为 `2 * (7 - 资质 / 15) * need_experience`；有关联武功且匹配槽熟练度等级小于 9 时为 `(等级 + 1) * (7 - 资质 / 15) * need_experience`，否则显示满级等号。机器整数除法均为向零截断。

## 汇编→C++收敛

本轮先从入口独立恢复两页背景分支、面板与头像、第一页全部字段和颜色、装备加成、升级阈值、第二页装备/修炼/武功循环、两次 present/任意键等待及全部出口，再对照 `BattleRenderer::render_character_status`、`BattleSession`、`GameMenuController`、`LegacyGameRuntime` 和 SDL 输入桥。

首轮发现两处位宽差异：机器对第一页当前经验执行 16 位零扩展后以 `%6d` 格式化，对第二页当前修炼经验执行 16 位零扩展后以 `%5d` 格式化；现代 renderer 原先使用有符号 `word()`。实现现改用 `unsigned_word()`，其底层为 `read_u16le`，不改变记录字节。测试新增原始字节分别为 `0x8001` 和 `0xFFFF` 的高位向量，第一页显示值按 `32769`、第二页按 `65535` 参与整帧计算。

修正后废弃首轮结论，并从 `0x22A59` 入口重新独立覆盖世界、场景、战斗三类背景，第一页各有符号/无符号读取、颜色和加成，第二页装备/修炼/武功分支，两次 present、任意非零键推进和返回写集；最终一轮零新增差异。

## 现代承接与平台适配

`BattleRenderer::render_character_status` 是三类调用上下文共用的逐像素 renderer。`BattleSession` 在战斗背景上显示两页；`LegacyGameRuntime` 在世界或场景重画后显示同一面板。原同步阻塞的 `sub_20C32` 由现代 phase continuation 和宿主键事件承接，每页仍只在已 present 后接受任意非零 legacy key；现代资源索引边界保护和宿主事件循环不改变当前合法资源及正常输入的可观察顺序。因此终态为 `platform_adapted`。
