# 函数证据：`sub_29537` `0x29537..0x295D0`

状态：`platform_adapted`

来源：当前 `Z.DAT`机器码、专用IDA批处理、两个caller上下文、原始场景工作档案、独立scene golden及现代快照/存档实现。

## 1. 物理身份

- 装载范围 `0x29537..0x295D0`，153 bytes、38条指令；原文件范围 `Z.DAT[0x22F37:0x22FD0]`。
- 原文件 SHA256：`dc433fc35fa2b4ebb8ab486995b4de8863b49bb6c5f8f09ee410270f12df6404`。
- 装载函数 SHA256：`e5d103d4ba35b736a4e3b4aa9143805971b94a8d7ddfc22c721f97b535092d64`。
- 9项绝对地址重定位全部满足 `loaded = raw + 0x20000`，规范化后逐字节一致。
- 两个直接caller为 `sub_2E337:0x2E37A` 和 `sub_2F721:0x2F783`；两者均先读取全局当前scene id并作为signed参数调用，且忽略返回值。

## 2. 入口到返回机器合同

函数参数是需要写回工作档案的当前scene id。

1. 固定栈探测后保存`ebx`。
2. 检查共享IDX cache tag是否为4；不是4时清偏移表并解析 `ALLSINBK.IDX`。打开失败打印原字符串后进入fatal终止链；成功后把tag设为4。
3. 以模式`0x202`打开 `ALLSINBK.GRP` 的写入路径并保存句柄。
4. 以参数scene id索引偏移表，执行绝对seek。
5. 从当前场景地图缓冲写固定`0xC000`（49,152）bytes到工作GRP当前记录。
6. 清理写调用参数，关闭句柄，恢复`ebx`并返回。

静态调用顺序固定为栈探测、IDX解析、错误打印/终止、工作GRP写入打开、seek、write、close。与order4不同，本函数包含完整write/close/ret尾，不跳入函数外读取块；其中 `0x295C2..0x295D0` 同时被邻接读取函数复用为共享关闭尾。

## 3. 两个caller的flush时点

### 单格外部场景修改

`sub_2E337`仅在显式scene不是`-2`时进入归档路径。它在打开目标scene之前，先用全局当前scene id调用本函数，把当前49,152-byte缓冲完整写回；之后才加载、修改并保存目标scene，最后由order4读取函数恢复原当前scene。当前KDEF的127次opcode17中有28次走此路径。

### 整层外部场景替换

`sub_2F721`的显式scene路径同样先调用本函数，再加载并整层替换目标记录，最后恢复当前scene。当前KDEF的3次opcode38都以`-2`修改当前场景，因此不触发该物理flush；合成显式scene回归覆盖完整路径。

若显式目标scene恰好等于当前scene，机器仍执行“flush当前→读同记录→修改→写回→重读同记录”；没有特判。

## 4. 汇编 → C++ 单向对照

现代 `GameSnapshot::scene_maps`本身就是100条场景记录组成的会话工作副本；`SceneSession::set_scene_value`直接把当前或显式目标scene的word写入对应span。因此不存在机器的“当前缓冲尚未写回工作GRP”中间态：

- 当前scene发生单格或整层修改时，同一快照span立即拥有最新值；
- 随后修改外部目标scene只访问目标span，不覆盖当前span；
- 显式目标等于当前scene时，对同一span直接修改，最终记录与机器路径一致；
- 读取进度会整体替换快照，保存进度由持久化层把全部场景span写入选定存档；
- 会话期工作副本从磁盘文件改为内存所有权，不改变游戏内后续读取、绘制或存档内容。

原机IDX失败后打印并终止，现代在完整快照导入前返回结构化错误；原机的GRP写失败及非法scene访问没有稳定业务恢复，现代写存档时返回错误并对非法索引稳定拒绝。这些均归类平台错误边界。

从入口重新复核38条指令、9项重定位、两个caller的flush-before-target顺序、完整写入尾和现代当前/目标span生命周期，零新增产品差异。
