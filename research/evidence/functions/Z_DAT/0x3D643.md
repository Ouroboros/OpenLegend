# 函数证据：`sub_3D643` `0x3D643..0x3D68A`

状态：`platform_adapted`

来源：当前 `Z.DAT` 机器码；`research/ida/reports/Z_DAT.b6_world_xrefs.txt`；`research/ida/reports/Z_DAT.targets.txt`；当前原版精灵资产。

## 1. 入口、门禁与调用者

- 物理范围`0x3D643..0x3D68A`，71 bytes、22条指令、4个基本块。入口先执行Watcom栈检查`sub_3ED1E(16)`。
- sprite id为32位参数：先有符号拒绝`<0`，再有符号拒绝`>0x7FFE`；两条失败路径均返回0且不读取指针表、不调用绘制核心。
- 合法非负ID以`sar/sub/sar`实现向零除2，在该域等价于整数floor除2；因此偶数ID与后一奇数ID共享frame，`0/1→0`、`2/3→1`、`0x7FFE→0x3FFF`。
- frame指针来自`dword_F87BC[index]`。anchor X/Y只取调用参数低16位并分别`movsx`为32位，再调用`sub_20354`；核心返回值被忽略，wrapper固定返回1。
- 七个机器caller覆盖标题/新建角色`sub_20FAF,sub_2711A`、world `sub_2558B`、scene `sub_29D2D`、物品菜单`sub_2A186`、结局`sub_30C3D`和battle `sub_3AA85`。

## 2. RLE委托边界

- `sub_20354 @ 0x20354..0x2050A`负责全部像素算法：解析`width,height,xOffset,yOffset`四个16位头，左上角为anchor减有符号offset，每行读取payload长度，再按`skip:u8,count:u8,pixels[count]`写320-byte stride后备缓冲。
- 核心分别跳过上/下不可见行，并裁剪左侧run前缀与右侧run后缀；`sub_3D643`本身不改变frame内容、anchor或裁剪顺序。
- wrapper的成功1只表示ID通过门禁并已委托；不转发核心寄存器返回值。

## 3. 汇编 → C++ 与适配

- `render::legacy_sprite_index`保持`0..0x7FFE`与`/2`映射；world/scene/标题/菜单/结局/battle调用点均以该索引取得对应归档entry，再交给`SpriteFrameView::parse`和`draw_rle_sprite`。
- 现代frame parser显式验证八字节头、每行边界、run长度、声明宽度和尾随字节，归档访问也检查entry数量；机器使用已加载裸指针表并依赖原资产有效。失败改为bool/typed error而非越界读取，属于平台适配。
- 现代anchor为宿主int并逐像素检查320×200边界；所有机器caller传入的低16位坐标与现代合法路径一致。
- 从入口重新核对栈门、上下界、除2、指针表、两个有符号anchor、核心委托及七个caller领域，并对`sub_20354`四向裁剪合同反向确认，零新增产品差异。

## 4. 验证与结论

- ID回归覆盖`-1,0,1,2,0x7FFE,0x7FFF`，固定共享frame与上下界；合成帧覆盖offset、透明skip、正常写入及右边界裁剪。
- 当前92个FIGHT归档加8个公共图像包，以及84对SDX/SMP和26对WDX/WMP中的78014个非空RLE帧全部解析，并分别在四个屏幕角实际绘制；四帧缓冲组合FNV1a64为`0xfce6bf593964e433`，同时覆盖上、下、左、右裁剪。
- world初始/天气/移动、scene六层、标题、新建角色、物品、结局与battle已有真实画面hash覆盖七类caller的有效ID路径。
- Linux app Debug：14/14通过，受管进程`proc_d9e8`。
- 原程序动态差分：`blocked_runtime_oracle`。
