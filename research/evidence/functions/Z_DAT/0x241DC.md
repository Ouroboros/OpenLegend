# 函数证据：`sub_241DC` `0x241DC..0x2422A`

状态：`platform_adapted`

来源：当前 `Z.DAT` 机器码；`research/ida/reports/Z_DAT.b6_world_xrefs.txt`。

## 1. 物理范围与调用边界

- 物理范围为`0x241DC..0x2422A`，78 bytes、14条指令、5个基本块；唯一直接caller是横向移动入口`sub_23C98`。
- caller有两个调用点：陆地步行成功或下船成功汇合到`0x23E15`后调用，以及乘船水域成功的`0x23E6E`分支调用。登船命中由另一分支直接从船主坐标恢复X，不调用本函数。
- 唯一被调函数是Watcom栈检查`sub_3ED1E`；本函数不读取Y、不判碰撞、不加载资源，也不写RANGER header。

## 2. 独立机器恢复

- 入口以参数`4`调用栈检查，随后读取唯一32位参数并直接加到32位world X。
- 加法后先按32位有符号数检查`<0`，命中则写0；再按32位有符号数检查`>479`，命中则写479。两个限制块次序固定。
- 最后以32位减法计算`world_x - cache_origin_x`，把结果写入cache-local X全局并保留在`EAX`返回。
- 唯一caller只传`-1/+1`，且只在碰撞成功后调用；合法可达坐标域不会触发32位溢出。caller不消费返回寄存器，随后才执行axis=0的cache提交。

## 3. 汇编 → C++ 映射

- `WorldSession::complete_move`在非登船的成功分支按`world_x_ + delta_x`并限制到`0..479`，承接陆地步行、乘船水域和下船三类调用路径。
- 现代不持久保存cache-local X，而由`cache_x()`实时返回`world_x_ - cache_.origin_x()`。`reload_cache_if_needed(false)`在提交前读取旧origin下的local阈值，必要时重载origin；重载后再次读取`cache_x()`即得到机器后续cache提交更新后的local值。
- 逐指令对照栈检查、32位加法、两个有符号限制、local减法、两处caller和返回值消费，未发现需要修改产品实现的差异。

## 4. 平台适配

- DOS可写全局dword改由`WorldSession`坐标与`WorldCache` origin持有；cache-local X从冗余状态改为按需派生，避免两份宿主状态失同步。
- 机器返回local X但caller不读取，现代因此没有独立返回接口；无效会话门禁由更外层移动入口承担。

## 5. 验证与结论

- 四方向连续移动固定cache-local X为`[65,65,64,64]`，直接覆盖向右提交、纵移保持X和向左提交。
- 原资产乘船向右从X=109提交到110时，cache origin X=44且`cache_x()==66`；横向连续可行路径从X=71、origin=7前进35步到X=106后重载origin=42，local X回到64。
- Linux app Debug：14/14通过，受管进程`proc_d62b`。
- 原程序动态差分：`blocked_runtime_oracle`。
