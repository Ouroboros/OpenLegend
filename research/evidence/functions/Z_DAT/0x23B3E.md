# 函数证据：`sub_23B3E` `0x23B3E..0x23C98`

状态：`platform_adapted`

来源：当前 `Z.DAT` 机器码；`research/ida/reports/Z_DAT.b6_world_xrefs.txt`。

## 1. 物理范围与调用边界

- 物理范围为`0x23B3E..0x23C98`，唯一直接调用者是world主循环`sub_20D35`；被调函数仅为Watcom栈检查`sub_3ED1E`与已终审的`sub_3D612` bounded RNG。
- 主循环在无输入恢复和待处理I/O之后调用本函数，随后才按active状态推进待机动画并render/present。scene返回后的world移动continuation也在render前恢复这条天气周期尾链。
- 唯一caller不读取返回值；本函数的游戏可观察结果是天气active、三个粒子的16位字段和共享RNG状态。

## 2. 独立机器恢复

- 入口以参数`12`调用栈检查并保存`EBX`。仅当16位active严格等于1时，按索引0、1、2依次把三个X坐标各加1。
- 三个X按顺序执行16位有符号严格`>500`检查；只有三者全部命中才把active清0。任一值`<=500`时保留active并跳过生成。
- 随后仅当active严格等于0时进入生成；异常非零值既不推进也不生成。inactive路径先调用`bounded(1)`，该调用固定返回0且不消费RNG，因此当前机器逻辑无条件生成。
- active在粒子字段生成前先置1。RNG调用按字段批次而非按粒子交错：三个`bounded(4)`写kind；三个`bounded(3)+6`写weight；三个`bounded(100)-300`写X。每次结果写入16位word。
- Y按粒子0、1、2处理。每个粒子先消费`bounded(2)`；非零分别写`-3000/-4000/-5000`，零则再消费`bounded(50)`并分别加`0/75/150`。
- active粒子的三个X在同一次调用中先递增；若本次递增后才使三者全部`>500`，本函数会同tick清active并立刻完整重建，不留一个inactive呈现tick。
- seed1首次生成共有15次逻辑bounded调用，其中`bounded(1)`不消费，实际消费14次；结果为kind`[2,2,1]`、weight`[7,7,8]`、X`[-290,-281,-288]`、Y`[49,-4000,160]`，最终RNG状态`0xAF1CF0FB`。

## 3. 汇编 → C++ 映射

- `WorldSession::periodic_tick`的有效会话门禁与`update_weather`承接全部状态。active时先逐粒子16位加1并累计`all_done`，未全部严格`>500`即返回；全部命中时清active并继续同tick生成。
- 现代生成保持机器批次顺序和Y的条件消费；`LegacyRandom::bounded(1)`保持无消费返回0，因此首次与重建RNG流一致。
- runtime保持天气周期位于待机动画之前；world进入scene时保留同一个`WorldSession`，返回后继续原天气状态，不因scene重建或额外生成粒子。
- 逐基本块对照active精确门禁、三个有符号阈值、同tick重建、全部RNG调用次序、16位写入、三个Y分支与caller顺序，未发现需要修改产品实现的差异。

## 4. 平台适配

- Watcom栈检查由宿主ABI承担；DOS全局word和三个并行数组改由`WorldSession`及三个`WeatherParticle`对象持有。
- 机器active是裸16位word，异常非零值会停留；现代私有状态为`bool`，只表示机器可达的0/1域。会话无效时现代安全返回，合法原资产行为不变。
- 唯一caller忽略机器返回寄存器，现代周期接口因此为`void`。
