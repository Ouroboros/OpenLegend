# 函数证据：`sub_247DD` `0x247DD..0x24A02`

状态：`platform_adapted`

来源：当前 `Z.DAT` 机器码；审计包 `tmp/startup-review/0x247DD.txt`

## 1. 独立机器恢复

- 入口无条件打开并整包读取 `CLOUD.GRP`；随后读取 `CLOUD.IDX`，将首offset固定为0，再由后续offset差建立5个云帧指针。
- 接着读取 `MMAP.COL` 的768字节调色板。
- 若RANGER IDX全局缓存标志不为1，则先把首offset写0，再读取 `RANGER.IDX` 到后续offset数组；失败时打印错误并等待键，成功路径把缓存标志置1。
- 打开 `RANGER.GRP`，按相邻IDX差依次读取六段：header、200角色、物品、scene状态区、scene-map区、scene-event区；每段读取前定位到对应offset，末尾关闭RANGER句柄。
- 本函数位于标题流程之前；云包、调色板、RANGER六段及IDX在标题出现前已经可用，IDX在后续编号槽读取中复用。

## 2. 汇编 → C++ 映射

- 标题前资源owner与严格加载顺序：`app::LegacyStartupResources::LegacyStartupResources`。
- 云包IDX解码及5帧span：`resource::PackedArchive`。
- 调色板：`LegacyStartupResources::palette()`，由标题与world renderer共享。
- RANGER六段：`persistence::load_baseline_ranger`、`RangerLoadResult`、`LegacyStartupResources::ranger()`。
- 新游戏只补读scene-map/event基线：`persistence::load_baseline_scenes`。
- 编号槽复用启动时IDX：`LegacyStartupResources::ranger_index_bytes()`、`persistence::load_numbered_slot(..., ranger_index_bytes)`。
- 云包和调色板由`LegacyGameRuntime`传给`WorldSession`；不在进入world时重复读盘。

## 3. 差异与整轮重启

1. 第一轮发现现代实现把RANGER基线、云包及调色板延迟到新游戏或首次进入world，并可能重复读取，违反本函数标题前无条件加载及IDX一次缓存边界；该轮立即废弃。
2. 修正为`LegacyStartupResources`在runtime构造时按机器顺序缓存资源，并让标题、新游戏、编号读档和world复用同一owner；RANGER与scene基线分层，使新游戏仅在原业务边界读取scene-map/event。
3. 从`0x247DD`入口重新恢复并逐基本块覆盖CLOUD.GRP、CLOUD.IDX、5帧指针、MMAP.COL、RANGER.IDX首次缓存、RANGER六段offset/长度及关闭出口。确认合法资产域零新增差异。
4. 重审caller `main`及callee `sub_26208`：前者在标题前完成本资源链，后者看到IDX已缓存而跳过再次读取；现代调用链保持相同可观察时点。

## 4. 平台适配

- DOS裸句柄、全局指针和固定工作区改为typed容器、只读span与RAII；后续使用者观察相同原始字节及帧边界。
- DOS错误路径的打印加等待键改为标题前typed启动错误；首个失败文件及失败时点保持。
- 安全读取会拒绝截断、损坏或越界IDX，不复刻宿主内存越界。
