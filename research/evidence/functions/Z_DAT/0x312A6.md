# Z.DAT `0x312A6` (`sub_312A6`) 最终审计证据

## 结论

- `Z.DAT:0x312A6..0x3192E` 是事件 opcode 64 使用的场景商店购买流程，完整范围 `1672` 字节、`473` 条指令。
- 当前 `Z.DAT` loaded bytes SHA256 为 `a8ac857e29c681aa581f539506ce0055526b3b5cccad17619ec46deae4a22980`，文件偏移 `0x2ACA6` raw bytes SHA256 为 `b5eb765deb1994347ca33820aaf9b78b75a29c8da36d712ef4d2a1fdda289597`。
- loaded/raw 有 `68` 项重定位；每项均为 raw 指针加 `0x20000`，归一化后逐字节一致。
- 唯一代码调用者是事件解释器 opcode 64。入口无参数，返回值固定为 `1` 且调用者不使用；调用完成后脚本 PC 增加 `1`。
- 当前 KDEF `script 938` 精确为 `(64, -1)`；原始两字参数流 SHA256 为 `df53d68c8b6ccc9346ed3ff3e2a4dbdf86eb26185f17ceac0a01d9a459774f1f`。
- 当前 `ALLDEF.GRP` 没有直接引用 script 938 的初始事件；五个合法商店事件由 opcode 65/script 939 动态启用。
- 最终 REVIEW 状态：`converged_no_new_differences`；运行时原程序动态差分仍记为 `blocked_runtime_oracle`。

## 合法场景与商店记录

- 机器分支只为下列场景写入商店号：`scene 1 -> shop 0`、`scene 3 -> shop 1`、`scene 40 -> shop 2`、`scene 60 -> shop 3`、`scene 61 -> shop 4`。
- 编译器序言调用 `sub_3EEC7` 只清零五个商品索引局部，不初始化商店号局部；scene 0 和其他场景不属于当前机器调用域。
- C++ 对五个合法场景保持精确映射；对非法场景稳定使用 `shop=-1` 并退出，替代原机未定义栈值访问，分类为 `platform_adapted`。
- 商店记录固定为 `5 x 30` 字节：五个物品 ID、五个库存、五个价格，均按有符号 16 位 word 读取；当前 150 字节记录 SHA256 为 `4a564910f1975cf21dbf9696a116ecba1d7d5206069a9e1a18b13f40afb909fa`。

## 机器流程

1. 显示 dialogue `2974`、head `111`、style `0`。
2. 顺序扫描五个物理商品槽；只把 signed stock `> 0` 的槽压缩进可见列表，选择索引属于压缩后的列表而非物理槽。
3. 初始选择为 `0`。面板参数为 `(94, 80, 140, visible_count*20+20)`；物品名位置为 `(104, 90+20*i)`；价格使用 `%3d`，位置为 `(200, 90+20*i)`。
4. 普通文字颜色为 `0x21/0x23`；当前选择颜色为 `0x05/0x07`。
5. 下键 `0x98` 和上键 `0x9E` 在非空可见列表首尾循环；Enter `0x0D`、Space `0x20`、`0x96` 都确认；Esc `0x1B` 取消。数字 `1..5` 不参与购买。
6. 确认后把可见选择映射回原物理商品槽，并只查找库存中第一个 item `174` 货币槽；重复货币槽不汇总。
7. 五个商品索引局部在序言被清零；可见列表全空时直接确认仍选择物理 slot 0。购买阶段不再次检查 stock，因此余额足够时会把 slot 0 的 stock 从 `0` 减为 `-1` 并取得该物品。空列表按上键会令机器选择索引成为 `-1` 并产生局部数组越界；C++ 对这条未定义导航稳定保持空选择。
8. 余额足够时顺序为：商店库存减一、扣减首货币槽、增加目标物品、重绘场景、显示 dialogue `2976`、再次重绘场景、关闭商人事件。
9. 余额不足或没有 item 174 时不改库存和物品，先重绘场景，再显示 dialogue `2975`，再次重绘后关闭商人事件。
10. Esc 取消不显示购买反馈，直接关闭商人事件。
11. 关闭事件精确为：scene 1 的 `17,18`；scene 3 的 `15,16`；scene 40 的 `21,22`；scene 60 的 `17,18`；scene 61 的 `10,11,12`。每次写入的十三个参数为 `(-2,event,0,0,-1,-1,939,-1,-1,-1,-2,-2,-2)`。

## C++ 对照与修正

- `SceneSession::run_event(case 64)` 保存真实商店号、压缩后的物理槽列表、可见数量和初始选择，并在 dialogue 2974 完成后进入协作式商店状态。
- `SceneSession::resume` 按原键值执行上下回绕、三种确认、Esc 取消、首货币槽判断及机器写入顺序；成功/失败反馈完成后才关闭事件。
- `SceneSession::render_shop_overlay` 冻结 dialogue 2974 最终 framebuffer，在其上按机器几何、文字、价格和颜色重建商店面板；不额外占用一份 64 KiB 会话 framebuffer。
- `LegacyGameRuntime::handle_key` 不再把数字 `1..5` 转换成物理槽购买；原版菜单键原样送入场景状态机，并按 SDL 键边沿/确认组规则清理键状态。
- 第一轮汇编→C++ REVIEW 发现并修正：scene 0 错映射 shop 0、数字快捷购买、未按正库存压缩列表、缺少原版面板和上下循环、购买写入顺序不符。
- 第二轮从入口重新 REVIEW，新增发现全空列表直接确认仍使用物理 slot 0 且购买不复核 stock；修正空列表确认和 stock 判断后再次废弃本轮结论。
- 第三轮从 `0x312A6` 入口重新逐块 REVIEW，覆盖合法五场景、非法域、空可见列表、选择回绕、确认/取消、首货币槽、成功/失败写入与事件关闭，未发现新增差异。
