# 函数证据：`sub_23AA6` `0x23AA6..0x23B3E`

状态：`platform_adapted`

来源：当前 `Z.DAT` 机器码；`research/ida/reports/Z_DAT.b6_world_xrefs.txt`。

## 1. 物理范围与调用边界

- 物理范围为`0x23AA6..0x23B3E`，24条指令、5个基本块；唯一直接调用者是world主循环`sub_20D35`，唯一被调函数是Watcom栈检查`sub_3ED1E`。
- 主循环先执行无输入恢复、待处理I/O和天气周期，再仅当idle-active word严格等于1时调用本函数，之后才render/present。因此本函数不消费RNG，也不在scene主循环中执行。
- world从scene返回后的同步移动continuation仍回到同一个主循环尾链；天气周期和本函数各执行一次，不提前或重复动画拍。

## 2. 独立机器恢复

- 入口以参数`4`调用栈检查，然后把16位delay加1；按有符号数严格比较`>3`。命中时先清delay，再把16位step加2。
- step按16位有符号数比较`<=12`。正常分支从方向索引表读取base和idle offset，以16位结果写当前world frame：`base[direction] + offset[direction] + step`。
- 报告的原始`BYTES`块固定base表`0x544E2 = {5002,5016,5030,5044}`，offset表`0x544EA = {54,52,50,48}`；方向顺序为up/right/left/down。
- 正常分支返回寄存器`AX`保留offset表值；唯一caller不读取返回值。
- step严格`>12`时依次清step、idle counter、active和delay，再把当前world frame恢复为方向base并返回该base。机器不在此分支重写walk offset；可达激活动画路径已在启动时把它清零。
- 激活tick由前序入口把step置为2，并在同一main迭代调用本函数。自该次调用计数，frame step序列为`2,2,2,4,4,4,4,6,6,6,6,8,8,8,8,10,10,10,10,12,12,12,12,base`；第24次调用产生step14并立即结束动画，不呈现step14帧。

## 3. 汇编 → C++ 映射

- delay/step/结束复位映射到`WorldSession::idle_animation_tick`；frame word映射到`WorldSession::player_frame`的即时计算。每个render观察到的frame与机器主动写word相同。
- `LegacyGameRuntime::advance`保持`idle_tick -> periodic_tick -> idle_animation_tick -> render`；scene返回的world移动continuation也在render前补执行`periodic_tick -> idle_animation_tick`。
- 现代方法内部对inactive会话提前返回，而机器由caller的`active==1`门禁保证不调用；合法调用域等价。
- 逐基本块对照栈检查、四拍delay、step有符号边界、四方向表、结束清态、frame结果、返回值和caller顺序，未发现需要修改产品实现的差异。

## 4. 平台适配

- Watcom栈检查由宿主ABI承担；DOS全局word改由`WorldSession`成员持有，当前frame按需计算。
- 唯一caller忽略机器返回值，现代接口因此为`void`。
- 原机器以裸16位方向索引访问表；现代从存档导入时把异常方向限制到`0..3`，并在结束分支冗余清零机器可达域中已经为0的walk offset。两项均为宿主内存安全边界，不改变合法原资产行为。

## 5. 验证与结论

- world回归覆盖四方向base/offset、完整24次调用frame序列、第3/4次delay边界、step12/14结束、结束后保持base及动画期间不额外消费RNG。
- Linux app Debug：14/14通过，受管进程`proc_d6d4`。
- 原程序动态差分：`blocked_runtime_oracle`。
