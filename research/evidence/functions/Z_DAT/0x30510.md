## 2. 不看C++的机器合同

入口对主角hurt word与50执行有符号比较；hurt按signed int16大于等于50时立即返回。hurt小于50才比较poison，只有poison精确等于0继续，任意正负非零值均立即返回。

满足条件时严格依次写：

```text
hurt = 0
physical_power = 100
current_mp = maximum_mp
current_hp = maximum_hp
```

maximum值按原word直接复制，不钳位；poison、两个maximum和所有其他角色数据不变。函数不扫描队伍且不触发对话、render、音频或额外等待。

## 3. 汇编→C++ REVIEW

`interround_fade`只取 `snapshot_.ranger.roles[0]`，以同一signed int16表达式 `hurt < 50 && poison == 0` 选择四项写入，顺序与机器相同。maximum MP/HP直接赋给current值，未引入合法域钳位或正值检查；其他角色完全不访问。

机器在同步fade和8-tick黑屏延迟后调用，C++只在带9 ticks的协作fade-to-black完成并resume后执行，再排入fade-from-black，故恢复的可观察时间边界一致。现代空角色数组保护仅处理损坏snapshot；当前原资产始终有role0，归类 `platform_adapted`。
