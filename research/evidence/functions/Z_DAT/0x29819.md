# 函数证据：`sub_29819` `0x29819..0x299A1`

状态：`platform_adapted`

来源：当前 `Z.DAT` 机器码；`research/ida/reports/Z_DAT.b7_scene_xrefs.txt`；独立 B7 oracle。

## 1. 独立机器恢复

- 函数共 392 bytes、87 条指令、26 个基本块，唯一显式参数为 signed step。
- 入口将 idle active `word_544F8` 与 20-tick `word_544F6` 清零，但保留 50-tick `word_544FA`、idle step `word_544FC` 和 delay `word_544FE`；随后步行动画 offset 加 2，大于 12 时回到 2。`step < 0` 写 direction 2（left），否则写 direction 1（right）。阻挡也不回滚这些副作用。
- 目标 x 为 `current_x + step`，随后裁剪至闭区间 `[0,63]`；y 保持不变。
- 按机器短路顺序检查：target building 必须为 0；signed `target_height-current_height < 10`；target event 为空，或其 `cannot_walk` 为 0；target earth 不得落入九个闭区间 `[358,362]`、`[374,380]`、`[458,464]`、`[506,610]`、`[818,824]`、`[838,838]`、`[934,936]`、`[1016,1022]`、`[1324,1348]`。
- 任一门禁失败即保留原 x 和 view origin；全部通过才提交 x，并将 view origin x 按 `x-11` 裁剪至 `[0,36]`。本函数不改 y 或 view origin y。
- 坐标在边界时仍先选择方向并推进步行动画；裁剪后的同格只要可行走，仍执行成功提交路径。

## 2. 全部 caller 与 C++ 映射

- 共有三个 caller、六个 callsite：`sub_26B5E` 新游戏 scene 主循环 `0x26EB6`；`sub_28E40` world 进入 scene 后的主循环 `0x28FB4`；`sub_2F171` opcode 30 脚本步行的四个象限分支 `0x2F1FD/0x2F248/0x2F293/0x2F2DB`。所有 callsite 只传 `+1/-1`。
- 键盘 caller 在 left→up→down→right 优先级中分别传 `-1/+1`；opcode 30 先走完整 x 轴，每步调用本函数、重绘并等待 100 DOS delay，再进入 y 轴。
- `SceneSession::move` 对应键盘 caller；`apply_scripted_walk_step(true, step)` 对应 opcode 30。共享 `target_is_walkable` 保持四级短路，`update_view_origin` 保持 `[0,36]` 裁剪，`player_frame` 使用 direction base 加 walk offset，`commit_header`承接机器全局坐标/方向提交。
- 现代实现对非法 scene/event 索引、损坏资产和 pending 状态进行边界保护；这些机器未定义域保护归平台适配，合法资产与全部真实 caller 域按汇编顺序一致。

## 3. REVIEW 与验证

1. 旧 inventory `research_name=scene_event_state_load` 与机器语义不符；本轮修正为 `scene_move_horizontal`。
2. 首轮逐块复核后继续检查共享 idle 字段 xref，发现现代 `cancel_player_idle_animation` 未清机器要求的 20-tick，反而清了机器移动时保留的 50-tick、idle step 和 delay。废弃首轮结论，将 helper 收窄为只清 active 与 20-tick。
3. 修正后从 `0x29819` 入口重新逐块复核状态清理、符号方向、目标裁剪、四级碰撞短路、成功/阻挡尾块、view origin 与全部六个 callsite，零新增差异。

## 4. 验证与结论

- 合成回归隔离 building、signed 高度差 10、event `cannot_walk`、九个 earth 闭区间双端点，并覆盖 x=0 向左、x=63 向右的同格裁剪及视口端点。
- 20 个 idle tick 后移动、再执行一个 idle tick仍保留walk帧，证明移动清零20-tick；50 个 idle tick 后执行最短 opcode 30，脚本结束后的下一 idle tick立即消费一次RNG，证明50-tick未被移动清零。既有scene70四向真实资产向量和opcode 30横向路径继续通过。
