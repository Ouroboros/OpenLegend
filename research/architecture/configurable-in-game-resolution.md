# 可配置 IN-GAME RESOLUTION 设计

## 1. 目标

`main` 支持彼此独立的两层分辨率：

- **WIN SIZE**：SDL 宿主窗口尺寸。它只把已经完成的游戏画面保持宽高比并尽量放大到窗口可用区域；只修改 WIN SIZE 时，可见游戏内容不变。
- **IN-GAME RES**：游戏实际绘制的逻辑画布。地图图块、人物和物件保持原逻辑像素尺寸；增大 IN-GAME RES 时，镜头显示更多地图内容。

渲染管线为：

```text
游戏状态与地图数据
→ 按 IN-GAME RES 绘制动态逻辑画布
→ Legacy Indexed 转 RGBA
→ Modern UI RGBA 合成
→ 按 WIN SIZE 计算最大等比 viewport
→ 提交到 SDL 窗口
```

例如：

```toml
[window]
width = 1920
height = 1080
maximized = false

[display]
width = 640
height = 360
```

此时游戏实际绘制 `640×360`，再以比例 `3` 显示为 `1920×1080`。世界、场景和战斗中的素材尺寸不变，但可见范围扩大。

## 2. 兼容合同

1. 未配置 `[display]` 时，IN-GAME RES 固定回退为 `320×200`。
2. `320×200` 路径必须继续使用原来的扫描范围、投影常量、画面特效和 UI 坐标，保持现有 golden 像素结果。
3. 可配置 IN-GAME RES 仅属于 `main`；`original` 不读取或消费该配置。
4. 不修改游戏状态坐标、碰撞、事件触发、脚本执行、随机调用、战斗 AI、寻路、存档格式或资产格式。
5. 扩展分辨率只增加已存在地图数据的可见范围。场景和战斗地图仍受其 `64×64` 数据边界限制，世界地图仍受其 `480×480` 数据边界限制。
6. WIN SIZE 使用保持宽高比的最大比例缩放；画面占满窗口的一边，另一边在比例不一致时居中留黑边，不拉伸变形。

## 3. 配置合同

新增：

```toml
[display]
width = 320
height = 200
```

规则：

- `width >= 320`；
- `height >= 200`；
- 宽高比不受限制，允许 `640×360`、`640×400` 等任意合理尺寸；
- 宽度上限为 `1280`，高度上限为 `800`，对应当前 Modern UI `64px` 字体上限并拒绝不受控分配；
- `[display]` 缺失，或 `width` 与 `height` 同时省略时，使用 `320×200`；
- `width` 与 `height` 必须同时提供或同时省略，仅提供其中一个属于配置错误；
- `[window]` 仍只保存和恢复宿主窗口尺寸；
- SDL 窗口最小尺寸随 IN-GAME RES 调整，保证至少存在 `1×` 整数显示倍率。

## 4. 动态画布

### 4.1 IndexedFramebuffer

`IndexedFramebuffer` 从固定 `320×200` 存储改为拥有动态宽、高和 stride 的索引色画布。

保留以下两类坐标空间：

- **Native 坐标空间**：覆盖完整 IN-GAME RES，用于世界、场景、战斗地图和与地图同尺度的特效。
- **Legacy UI 坐标空间**：输入仍为原版 `320×200` 坐标，写入时 nearest-neighbor 映射到动态画布中按比例居中的 UI viewport。

Legacy UI viewport 使用 `320:200` 比例完整容纳于 IN-GAME RES：

```text
ui_scale = min(game_width / 320, game_height / 200)
```

映射允许在逻辑画布内部使用非整数比例，以支持 `640×360` 等任意宽高比；最终 WIN SIZE 同样按最大等比 viewport 连续缩放。

地图渲染函数进入 Native 坐标空间；菜单、对话框、标题、属性页、死亡画面和结局画面默认使用 Legacy UI 坐标空间。这样地图素材不放大，而 UI 随 IN-GAME RES 按比例放大。

### 4.2 RGBA 画布

Legacy RGBA 转换缓冲和 Modern UI RGBA 缓冲都按动态 IN-GAME RES 创建：

- Legacy RGBA：`game_width × game_height`；
- Modern UI RGBA：`game_width × presentation_scale` 乘 `game_height × presentation_scale`；
- `presentation_scale` 取最接近最终显示比例的正整数，用于生成足够清晰的 Modern UI 字形，不再决定 SDL 目标矩形尺寸。

### 4.3 SDL 提交

Legacy 纹理与 Modern UI 纹理都允许按输入尺寸重建。SDL viewport 改为：

```text
scale = min(output_width / game_width, output_height / game_height)
viewport_width = game_width * scale
viewport_height = game_height * scale
```

窗口最小尺寸继续保证 `scale >= 1`。Legacy 与 Modern UI 使用同一个浮点目标矩形和 nearest-neighbor 采样；目标矩形占满窗口的一边，并在另一边居中留黑边。

### 4.4 调色板淡变失效边界

FI/FO 的静态索引像素与逐帧调色板分开失效：

- 淡变首帧正常生成标题、等待页、世界、场景或战斗画面的索引像素，并据此生成完整调色板序列；
- 同一次淡变的后续帧复用该索引像素，只替换当前调色板；
- Legacy Indexed 转 RGBA、Modern UI 更新和 SDL 提交仍逐帧执行，保证每个调色板阶段实际可见；
- 开始新的淡变、切换底层画面或结束当前状态机阶段时，旧调色板序列失效，下一阶段重新生成所需像素；
- 淡出保持 64 帧，淡入保持 65 帧，不改变等待周期、随机调用和状态推进顺序。

此边界避免 IN-GAME RES 增大后，每个调色板帧重复扫描地图并执行 RLE 精灵绘制。索引色转 RGBA 使用每帧 256 色展开表，避免为画布中的每个像素重复执行 RGB6 换算。

## 5. 地图镜头

### 5.1 投影锚点

原版地图脚点锚点为 `(145, 117)`。它相对 `320×200` 几何中心的偏移是 `(-15, +17)`，该偏移来自未缩放素材的脚点几何，因此扩展模式不按 UI 比例放大：

```text
anchor_x = game_width / 2 - 15
anchor_y = game_height / 2 + 17
```

人物视觉中心因此继续接近画布中心，新增视野分布在人物四周。

### 5.2 世界地图

- 默认 `320×200` 保留原 `32×32` 扫描路径。
- 扩展模式使用独立的 `128×128` 绘制缓存，并在玩家移动后重新以玩家为中心装载；原移动、碰撞缓存继续保持机器码的重载时机。
- 地面、表面、建筑及人物共用新的动态投影锚点。
- 深度列表接受动态缓存扫描边界，但保留原排序规则。
- `128×128` 缓存足以覆盖设定的安全分辨率上限；超出缓存的候选格不读取。
- 天气粒子不改变随机状态或更新节奏；扩展画布通过重复原粒子场覆盖新增区域。

### 5.3 场景

- 默认 `320×200` 保留原 `28×28` 扫描路径和 `view_origin` 行为。
- 扩展模式以 `view_origin + (11, 11)` 为镜头参考格，在完整 `64×64` 场景范围内投影和裁剪。
- 玩家、建筑、事件图像和装饰仍按原顺序绘制。
- 场景边缘以黑色清屏后绘制有效地图，不读取地图外数据。
- `SDX/SMP` Sentinel archive 的零长度条目是合法透明帧；扩展视野扫描到此类旧镜头外事件时按 no-op 处理，非空损坏条目仍返回错误。
- 阴影遮罩不增加随机调用；原 `320×200` 遮罩重复覆盖新增画布区域。

### 5.4 战斗

- 默认 `320×200` 保留原 `32×32` battle render plan。
- 扩展模式以 `state.view + (11, 11)` 为镜头参考格，对完整 `64×64` 战场生成投影命令。
- 地形、物件、角色、攻击区域、光标、伤害文字和特效继续使用原深度顺序。
- 战斗逻辑仍使用原 `view_x/view_y`、寻路、攻击范围和 AI；只改变 render plan 的可见投影。

## 6. UI 与完整画面

用户选择所有画面采用 IN-GAME RES，并要求 UI 同步等比放大。

- Legacy 菜单、对话框、标题、属性页和战斗面板继续使用 `320×200` 参考坐标，通过 Legacy UI 坐标空间映射到动态画布。
- 标题、死亡和结局等固定 `320×200` 像素资源先清空动态画布，再按比例绘制到居中的 Legacy UI viewport；宽高比不一致时保留黑边。
- 地图上的 Legacy UI overlay 在动态地图之上绘制，不把地图退回原视野。
- Modern 存档列表根据动态画布布局，字体和间距按 Legacy UI 比例增大。
- Modern 位置 HUD 根据动态画布边缘锚定，字号和 inset 按 Legacy UI 比例增大。

## 7. 边界与风险

### 已验证事实

- 世界地图数据为 `480×480`。
- 世界渲染缓存为 `128×128`。
- 场景和战斗地图数据均为 `64×64`。
- 当前 framebuffer、投影中心、扫描范围、阴影遮罩和多个 UI renderer 直接依赖 `320×200`。

### 可推导风险

- 扩大场景视野可能显示原脚本预期位于旧镜头外的人物、图像切换或布置过程；这不改变脚本，但会改变玩家可见信息。
- 视野面积增加会提高 tile/sprite 遍历和绘制成本。
- 任意宽高比会使地图新增空间与 `320:200` UI viewport 不完全重合；新增侧边或上下区域继续显示地图，完整画面资源则显示黑边。

## 8. 验证策略

1. 配置测试：缺失、合法任意宽高、低于最小值、异常大值、错误类型、稳定写回和未知字段丢弃。
2. viewport 测试：不同 WIN SIZE 与 IN-GAME RES 的最大等比缩放、居中和黑边。
3. framebuffer 测试：动态宽高、stride、裁剪、Legacy UI 坐标映射和完整画面缩放。
4. 世界测试：默认 golden 不变；扩展画布四周存在新增地图像素；玩家投影位置正确。
5. 场景测试：默认 golden 不变；扩展模式访问完整 `64×64` 合法范围；边界不越界；场景 58 在 `1280×720` 下可呈现入场动画产生的透明占位帧。
6. 战斗测试：默认 render plan 不变；扩展 plan 包含旧视野外的合法地图命令；逻辑状态不变。
7. UI 测试：`640×400` 为严格 `2×` Legacy UI；`640×360` 使用居中、保持比例的 UI viewport。
8. 淡变测试：标题、等待页和世界淡变的第二帧必须保留首帧后注入的哨兵索引像素，证明只更新调色板；既有像素 golden 与帧数保持不变。
9. Windows Release + ASan BUILD，部署 EXE、PDB 和 ASan DLL；不主动启动游戏，不运行 CTest，等待实机确认。
