1.1 数据事实与术语

  • WAR.STA中的经验是整场战斗总经验，不是单个敌人的经验。
  • 战斗结束后先按原规则确定胜负、存活资格和人数，再得到每名角色的原始个人奖励e0。
  • 下文所有“战斗所需场数”均使用整场总经验且不做队伍分配；多人存活时，每人的实际经验还要先按原规则分配。
  • 原版当前数据中，战斗99由5名番僧组成、整场经验450且可以重复触发，因此用作低收益可重复战斗样本；程序仍按战斗定义读取。
  • 秘笈修炼经验指item_experience；它与战斗中使用武功获得的1／2点熟练度不是同一个系统。

1.2 人物数值继承

本节处理原版角色记录中已经存在的字段，并额外包含已经明确批准的no_magic_count[ItemCount]。

除该字段外，其他NG+新增字段、装备物品自身记录、库存、队伍、剧情状态和其他系统设计不属于本节。

1.2.1 范围与通用公式

Prev(r,f) = 源通关TOML的[[roles]]中角色r的完整逻辑字段f
Base(r,f) = 当前原版RANGER角色定义中的字段f
HurtMax(n, CFG) = 保留的第n周目内伤状态上限，定义见内伤医疗页内伤章
中毒量正常范围固定为0～99；其他直接继承字段不以n限幅
EverJoined(r) = 角色r是否曾在任一周目实际加入过队伍
RoleId(r) = r                                  # 固定身份不变量
HeadId(r) = Base(r,head_id)                     # 固定头像定义，不写入TOML

TOML中的角色ID重复、越界或顺序错误：拒绝转换
Legacy源存档中的角色ID或head_id与当前原版角色定义不一致：拒绝转换

不参与继承且不受EverJoined范围限制的原版字段集合：
FreshFields = { sex, taking_items[4], taking_counts[4] }
对于所有角色r和f∈FreshFields：
Next(r,f) = Base(r,f)

其中角色携带物的恢复必须逐角色读取当前原版数据：
Next(r,taking_items[0..3]) = Base(r,taking_items[0..3])
Next(r,taking_counts[0..3]) = Base(r,taking_counts[0..3])
不得硬编码任何角色ID、物品ID或数量
不得在NG+转换阶段调用、重放或模拟KDEF剧情脚本

对所有角色r：
Next(r,make_item_experience) = 0

对于FreshFields与make_item_experience以外的字段，若 EverJoined(r)=false：
Next(r,f) = Base(r,f)

对于FreshFields与make_item_experience以外的字段，若 EverJoined(r)=true且字段采用直接继承：
Next(r,f) = Prev(r,f)  # 不作跨周目数值clamp；固定枚举与存储有效性另行验证

对于FreshFields与make_item_experience以外的字段，若 EverJoined(r)=true且字段恢复原版基线：
Next(r,f) = Base(r,f)

name与nickname继承逻辑字符串并执行UTF-8→Legacy Big5验证；
资源引用和数组槽位不使用数值clamp，复制后执行合法性验证。

角色ID与头像ID都属于固定角色定义，不参与继承、重置或clamp；TOML只保存角色ID，头像ID始终从当前原版角色定义读取。

性别与角色原版携带物不受历史入队范围限制：所有角色进入新周目时都从当前原版角色定义恢复这些字段，不继承上一周目的变化。

这样敌人重新取得原版战斗携带物，可入队角色也能按原流程在每个周目转交一次原版物品。

除上述恢复字段及统一清零的make_item_experience外，只有曾经真正加入过队伍的角色才执行下面的逐字段转换；未入队角色不写入TOML，新周目其他字段使用当前RANGER角色基线。

敌方出战抗毒从当前GAME DATA角色的BASE累加每周目STEP；其他有STEP的敌方字段按敌方成长总表计算。详见抗毒章。

直接继承完整复制实际值，不按目标周目数值节点补值或夹值；固定枚举、资源引用及存储可表示性依各自字段验证，不静默修复损坏存档。

1.2.2 原版字段转移与数值边界登记

各字段页的“下一周目值”只表示换周目处理；内伤的运行期周目上限、中毒量的固定0～99范围与其他字段的固定域分别记载。其余人物数值不再有逐周目上限，不能把下文旧CFG增量对照当作硬上限。

逐字段转移表已迁入各字段的独立页面；由主页逐一进入。

数值边界登记（原版基值、保留上限与既有CFG）

原版NG1基值、默认CFG及用户实际CFG分开读取。仅hurt保留随周目增长的状态上限HurtMax(n, CFG)，poison正常范围固定为0～99；体力固定100，资质、枚举、角色当前HP／MP与其实际最大值的关系仍按各自规则验证。

其他数值的旧周目增量不再用于继承或写回限幅；抗毒STEP用于敌方逐周目累加；等级、武功、生命、内力、武力、防御的既有STEP仍分别供敌方周目增长，等级和武功STEP也用于对照表节点。状态字段换周目清0不等于状态上限为0。

只对已有依据的参数保留默认数值，不互相借用增量。

各字段页分别保留原版范围、既有CFG数值与当前规则；不得把历史上限示例当成现行硬上限。

内伤的周目上限按内伤医疗页使用当前CFG计算，中毒量按固定0～99验证；其他字段只执行自己的固定有效域、角色实际最大HP／MP及存储合同，不以周目节点拒绝合法值。

原版中毒100是特定写入路径的机器事实；NG+施毒见中毒章“上毒”。医疗距离、解毒量和施毒规则分别见对应字段页。

1.2.3 转换顺序与示例

  1. 从当前原版RANGER.GRP读取角色基线与字段合法域。
  2. 判断角色是否属于“曾在任一周目实际加入过队伍”的名单。
  3. 所有角色先从当前RANGER建立基线并恢复FreshFields，再将make_item_experience清0；对其余字段，不在名单中的角色保持当前RANGER基线，在名单中的角色按第1.2.2节逐字段处理。
  4. 先继承level、maximum_hp、maximum_mp等数值， 再恢复hp、mp和physical_power。
  5. 继承并验证每名适用角色的no_magic_count[ItemCount]；它不随当前practice_item清空。
  6. 最后验证全部ID、字符串、数组槽位和数值范围；失败时拒绝转换，不静默修复损坏存档。
数值示意（不是代码常量）：
上一周目 maximum_hp=845、hp=213 → 下一周目 maximum_hp=845、hp=845
上一周目 maximum_mp=620、mp=75  → 下一周目 maximum_mp=620、mp=620
上一周目 hurt=40、poison=25      → 下一周目 hurt=0、poison=0
任一角色上一周目 sex发生变化 → 下一周目不继承，统一取Base(r,sex)；主角原版数据结果为0（男）
任一角色上一周目携带槽已清空      → 下一周目taking_items/counts恢复为Base(r,f)
上一周目 attack=138              → 下一周目 attack=138（不按周目夹值）

角色已经练出的等级、最大生命／内力及能力不会因换周目损失，也不会由周目增加自动赠送实际数值；仅明确指定恢复、清零或清空的字段另作处理。内伤与中毒换周目清0；运行期内伤仍使用本周上限HurtMax(n, CFG)，中毒量正常范围固定为0～99。
