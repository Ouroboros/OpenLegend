1.1 数据事实与术语

  • WAR.STA中的经验是整场战斗总经验，不是单个敌人的经验。
  • 战斗结束后先按原规则确定胜负、存活资格和人数，再得到每名角色的原始个人奖励e0。
  • 下文所有“战斗所需场数”均使用整场总经验且不做队伍分配；多人存活时，每人的实际经验还要先按原规则分配。
  • 原版当前数据中，战斗99由5名番僧组成、整场经验450且可以重复触发，因此用作低收益可重复战斗样本；程序仍按战斗定义读取。
  • 秘笈修炼经验指item_experience；它与战斗中使用武功获得的1／2点熟练度不是同一个系统。

1.2 人物数值继承

本节处理原版角色记录中已经存在的字段，并额外包含已经明确批准的unassociated_manual_success_counts[ItemCount]。

除该字段外，其他NG+新增字段、装备物品自身记录、库存、队伍、剧情状态和其他系统设计不属于本节。

1.2.1 范围与通用公式

Prev(r,f) = 源通关TOML的[[roles]]中角色r的完整逻辑字段f
Base(r,f) = 当前原版RANGER角色定义中的字段f
Cap(f,n) = 按当前规则集与运行时CFG求得的字段f在第n周目的合法上限
EverJoined(r) = 角色r是否曾在任一周目实际加入过队伍
RoleId(r) = r                                  # 固定身份不变量
HeadId(r) = Base(r,head_id)                     # 固定头像定义，不写入TOML

TOML中的角色ID重复、越界或顺序错误：拒绝转换
Legacy源存档中的角色ID或head_id与当前原版角色定义不一致：拒绝转换

不参与继承且不受EverJoined范围限制的原版字段集合：
FreshFields = { sexual, taking_items[4], taking_counts[4] }
对于所有角色r和f∈FreshFields：
Next(r,f) = Base(r,f)

其中角色携带物的恢复必须逐角色读取当前原版数据：
Next(r,taking_items[0..3]) = Base(r,taking_items[0..3])
Next(r,taking_counts[0..3]) = Base(r,taking_counts[0..3])
不得硬编码任何角色ID、物品ID或数量
不得在NG+转换阶段调用、重放或模拟KDEF剧情脚本

对于FreshFields以外的字段，若 EverJoined(r)=false：
Next(r,f) = Base(r,f)

对于FreshFields以外的字段，若 EverJoined(r)=true且字段采用直接继承：
Next(r,f) = clamp(Prev(r,f), Min(f), Cap(f,n))

对于FreshFields以外的字段，若 EverJoined(r)=true且字段恢复原版基线：
Next(r,f) = Base(r,f)

name与nickname继承逻辑字符串并执行UTF-8→Legacy Big5验证；
资源引用和数组槽位不使用数值clamp，复制后执行合法性验证。

角色ID与头像ID都属于固定角色定义，不参与继承、重置或clamp；TOML只保存角色ID，头像ID始终从当前原版角色定义读取。

性别与角色原版携带物不受历史入队范围限制：所有角色进入新周目时都从当前原版角色定义恢复这些字段，不继承上一周目的变化。

这样敌人重新取得原版战斗携带物，可入队角色也能按原流程在每个周目转交一次原版物品。

除这些字段外，只有曾经真正加入过队伍的角色才执行下面的逐字段转换；未入队角色不写入TOML，新周目直接使用当前RANGER角色基线。

直接继承不是把数值补到新上限，而是先复制实际值，再防止非法越界。

1.2.3 转换顺序与示例

  1. 从当前原版RANGER.GRP读取角色基线与字段合法域。
  2. 判断角色是否属于“曾在任一周目实际加入过队伍”的名单。
  3. 所有角色先从当前RANGER建立基线并恢复FreshFields；对其他字段，不在名单中的角色保持当前RANGER基线，在名单中的角色按第1.2.2节逐字段处理。
  4. 先处理level、maximum_hp、maximum_mp等上限依赖字段， 再恢复hp、mp和physical_power。
  5. 继承并验证每名适用角色的unassociated_manual_success_counts[ItemCount]；它不随当前practice_item清空。
  6. 最后验证全部ID、字符串、数组槽位和数值范围；失败时拒绝转换，不静默修复损坏存档。
数值示意（不是代码常量）：
上一周目 maximum_hp=845、hp=213 → 下一周目 maximum_hp=845、hp=845
上一周目 maximum_mp=620、mp=75  → 下一周目 maximum_mp=620、mp=620
上一周目 hurt=40、poison=25      → 下一周目 hurt=0、poison=0
任一角色上一周目 sexual发生变化 → 下一周目不继承，统一取Base(r,sexual)；主角原版数据结果为0（男）
任一角色上一周目携带槽已清空      → 下一周目taking_items/counts恢复为Base(r,f)
上一周目 attack=138              → 下一周目 clamp(138, Min(attack), Cap(attack,n))

角色已经练出的等级、上限和能力不会因为换周目消失；新周目也不会自动赠送任何新增上限。只有明确指定为恢复、清零或清空的原版字段会发生变化。
