NG+主设计

敌方成长与战斗结算

本页串联正式字段规则与原版结算顺序。已确定的NG+规则替换对应步骤，未改变的公式、分支及随机调用顺序沿用原版；角色与战斗数值使用经检查的signed64运算。文档收录不代表运行时代码已经实现。

敌方从基线累加STEP

n为当前周目，NG1取1；BASE为当前GAME DATA的RANGER角色基值。每次生成敌方均从BASE计算，NG2增加一次STEP，NG3增加两次STEP。

敌方字段(n) = BASE字段 + (n − 1) × 对应STEP
敌方字段读取的CFGSTEP单位
maximum_hphp_cap_step最大生命点数
maximum_mpmp_cap_step最大内力点数
attackattack_cap_step武力点数
defencedefence_cap_step防御点数
use_poisonuse_poison_cap_step用毒点数
anti_poisonanti_poison_cap_step抗毒点数；字段说明见抗毒章
hidden_weaponhidden_weapon_cap_step暗器技巧点数
levelrole_level_step人物等级
已学武功槽的magic_levelsmartial_level_step武功等级；每级对应100熟练度

武功等级换算仍按秘笈修炼规则，保留BASE熟练度的余数：

敌方已学武功熟练度(n) = BASE熟练度 + 100 × (n − 1) × martial_level_step

无对应STEP的字段及其他战斗准备步骤沿用原版；空武功槽保持空槽。上述生成直接计算字段值，不触发人物升级随机成长。敌方不继承上一周目的战斗剩余状态，不套用我方曾入队角色继承值；我方按人物继承处理。

例如BASE最大生命600、hp_cap_step=999，NG1／NG2／NG3分别为600／1599／2598；BASE抗毒33、anti_poison_cap_step=100，分别为33／133／233。字段不按周目参考节点封顶；生成时检查signed64范围及字段合法域，非法结果拒绝。

实现状态：实际游戏入口已把启动时读取的当前RANGER基线传入战斗，先解码完整敌方角色，再用calculate_enemy_attributes计算表中增长字段。敌方状态只在本场战斗内存在，同侧重复ID共享同一角色，双方相同ID分别取敌方基线与我方运行状态。攻击、医疗、解毒、物品、AI、移动、显示及战后恢复／经验写入均按参战槽和阵营取角色，敌方变化不写回我方继承记录；人物升级、秘笈和制作仍只处理原本具有战后提示资格的我方角色。

当前HP／MP保留BASE原值，不因最大值增长额外补满；原敌方追加函数只登记参战槽和占位，没有入场补满步骤。当前资产角色83与90的MP为95、最大MP为90，原值例外保留；负STEP降低最大值后若当前HP／MP超过新最大值，则拒绝生成。全部敌方计算成功后才提交本场敌方容器，不消耗RNG。低层构造未提供基线时保留预置角色入口，不执行敌方增长；实际游戏入口始终显式传入资产基线。

一次出招的完整顺序

  1. 取得参战角色的实际字段、当前武功熟练度和周目装备加成。
  2. HP型武功按当前内力选择实际出招等级，再计算该等级的武功威力。
  3. 对每个命中目标计算攻防总量、主伤害及低伤害分支。
  4. 按原版顺序加入体力和目标内伤修正，再应用距离衰减与最少1点伤害。
  5. 记录攻击计数，扣HP，以计算伤害增加内伤，再结算武功附毒及毒溢出。
  6. 武功熟练度增长、耗内、体力和攻击次数按原版动作提交时机处理；各项已定NG+数值规则仍适用。

内力型武功走下方独立MP分支。武功威力或合并效果是伤害公式的输入；几何权重、耗内补偿与等级成长只在武功效果成长中计算一次。

HP型武功的出招等级与威力

熟练等级 = trunc(实际熟练度 / 100) + 1
等级耗内(候选等级) = trunc(候选等级 / 2) × 武功基础耗内

从熟练等级向下选择当前MP能够承担的最高等级；1级耗内为0。1～10级威力读取对应原始数组；11级及以后用已定扩展效果得到攻击威力，射程、半径和形状使用原10级状态。效果公式不读取周目号，不在最终扣血时再乘武功成长倍率。

选目标的射程、半径和形状沿用原版选格流程读取的熟练等级，11级以后冻结为原10级状态；HP计算中的内力降档只改变威力与耗内，不重新选格。原版选档和耗内关系见sub_39188。武功附毒使用降档前的熟练等级。

HP伤害主干

攻防总量

每件装备的攻击、防御加成及固定武器—武功搭配加成按装备页计算。符合原版资格的参战者贡献2倍武学常识：knowledge严格大于80、HP大于0且非隐藏；同方计入攻方常识，对方计入防方常识。

攻方总量 = trunc((3 × 攻击者实际attack + 本次武功攻击威力) / 2)
           + 攻击者两件装备攻击加成
           + 本次武器—武功搭配攻击加成
           + 同方常识贡献
防方总量 = 目标实际defence
           + 目标两件装备防御加成
           + 对方常识贡献

主伤害与低伤害分支

基础伤害 = trunc(2 × (攻方总量 − 3 × 防方总量) / 3)
           + bounded(20) − bounded(20)
若基础伤害 ≤ 0：
  基础伤害 = trunc(攻方总量 / 10) + bounded(4) − bounded(4)

两个bounded(20)始终按顺序调用；只有主伤害非正才调用两个bounded(4)。bounded沿用原版随机函数的边界与状态消费规则。trunc为向零取整，不能把多个除法合并后统一舍入。

体力、内伤与距离

若低伤害分支计算后仍为负：
  计算伤害 = 1
否则：
  修正伤害 = 基础伤害
             + trunc(攻击者physical_power / 15)
             + trunc(目标hurt / 20)
  若距离 ≤ 10：
    距离后伤害 = trunc(修正伤害 × (100 − 3 × (距离 − 1)) / 100)
  否则：
    距离后伤害 = trunc(修正伤害 × 2 / 3)
  计算伤害 = max(距离后伤害, 1)

负的低伤害结果跳过体力、内伤和距离修正；恰好0仍进入这些修正。目标内伤增伤按实际hurt除20，依内伤页，此处不换算为伤势百分比。原版完整分支、四次随机调用条件与写回顺序见机器合同。

扣血、产伤及攻击计数

攻击计数 += trunc(计算伤害 / 5)
扣血后值 = 目标扣血前HP − 计算伤害
目标HP = max(扣血后值, 0)
若扣血后值 < 0：攻击计数 += 10 × 目标实际level
目标hurt = min(本周HurtMax, 目标旧hurt + trunc(计算伤害 / 10))

计算伤害用于攻击计数及产伤，不能先按目标剩余HP截短。沿用原版严格边界：扣血后恰好0也死亡，但不触发这次额外击倒计数；严格低于0才增加10倍目标等级。本周HurtMax由实际CFG计算，见内伤章。

随后结算武功附毒

毒力使用角色实际武功带毒与武功带毒字段乘降档前熟练等级，除数15；统一按上毒公式计算最深、实际毒入、溢出与即时扣HP。附毒不再次应用攻防、距离或武功攻击威力倍率。溢出和每轮毒伤均可致死。溢出伤血不额外增加内伤；当场伤血大于0时单独追加伤血飘字。

内力型武功

沿用sub_395EC的MP结算分支：读取实际熟练等级对应的削减／恢复量；11级以后两项由武功效果成长计算。原版此分支不使用HP型的耗内降档、攻防、距离、体力或内伤增伤。

  1. 保存目标MP旧值，按顺序抽取两个bounded(3)，得到攻击者随机差。
  2. 攻击者当前MP增加该级恢复量；再调用bounded(trunc(恢复量 / 2))增加最大MP。
  3. 攻击者当前MP加先前随机差，按已定MP合法域限制在0至实际最大MP之间；最大MP不按999或周目参考节点封顶。
  4. 按顺序抽取两个bounded(3)，得到目标随机差；目标当前MP减该级削减量再减随机差，结果不大于0时写0，并遵守当前MP不超过实际最大MP的字段约束。
  5. 返回目标旧MP减目标最终MP；攻击者与目标为同一角色时，仍按原版先恢复后削减的顺序。

五次随机调用及其条件消费规则沿用原版；原版16位回绕、最大MP的999封顶由已经确定的64位与永久能力合同替换。

玩家与AI投掷暗器

保留原版先完成EFT动画再读取实际载荷的顺序；队伍AI仍从最近一次玩家确认槽读取载荷，动画与消耗使用本次来源槽，敌方AI使用自身来源槽。完整机器依据分别见玩家投掷与AI投掷。

H=0时，除数=4
H>0时，以100×H与33×B、66×B比较，依次取除数3、2、1
随机基数 = trunc(item.add_hp / 除数) − bounded(5)
HP变化 = trunc((随机基数 − 2×actor.hidden_weapon) / 3)
新内伤 = clamp(H − trunc(HP变化 / 4), 0, HurtMax)
主结算HP = clamp(原HP + HP变化, 0, MAX HP)
原伤害数字 = abs(主结算HP − 原HP)

上述运算使用检查溢出的signed64。正毒采用毒力trunc((item.add_poison＋actor.hidden_weapon)/2)、除数2的统一上毒；溢出在主HP结算后扣血，最低0，不额外产伤、不增加击倒奖励，独立追加伤血数字。主HP差为0而有毒溢出时也进入伤害数字显示。

玩家零／负毒仍为trunc(V/2)＋bounded(5)−bounded(5)，在伤害随机之后依次消费两个随机数；AI零毒增量0，负毒仍为trunc((V−W)/2)且不追加中毒随机数。中毒写回夹0至99。单次载荷计算失败保留HP／内伤／中毒、随机状态与伤害计数；目标准备、动画及库存提交仍有独立边界。

射程仍按实际技巧向零除15再加1。进入原有signed16目标选择器时，正向超出表示范围的距离取32767；选择器读取的路径距离本身为signed16，因此可选格及AI距离比较结果不变。角色技巧、伤害和毒力不受该表示转换限制。来源库存或敌方携带数量按64位减1，非正结果仍沿原槽位左移。

普通物品的结算与显示

菜单、玩家及AI使用共享物品效果入口。内伤折算、正向回血倍率及两条内伤写回按内伤页；正毒按统一上毒。回血倍率的原版NG1最大生命基准从当前Z.DAT规则读取，当前为999。

保留原版物品顺序：先当前HP、最大HP，再毒、体力、内力类型、当前MP、最大MP及其余字段。最大HP／MP与能力使用检查过的64位加法，取消16位回绕和999封顶，原下界、体力100及HP／MP不超过实际最大值的约束保持。品德和左右互搏仍只列入原效果数组，不写角色字段。

药品负毒保留两次bounded(5)，不读取使用者能力；正毒溢出在原HP效果之后扣血，最低0且不额外产伤。23项效果值完整显示signed64，长数字按需要展开面板；毒溢出单独追加生命减少行，只有溢出有伤血时也显示并构成有效效果。

单次效果计算失败不提交目标和随机状态；AI同步扣来源失败也恢复这两者。菜单和玩家仍在有效果且画面呈现后消费并等待按键，玩家全零效果不扣库存；AI仍等待9次tick后扣队伍库存或携带槽。各调用者的呈现、等待与库存提交保留独立边界。

角色医疗的结算与显示

菜单、玩家和AI读取当前周目HurtMax，按医疗页的连续倍率计算共同治疗量Q。回血只限于非负HP缺口，治伤独立限制到当前内伤；满生命也能治伤。此路径不使用药品的MAX HP／原版NG1上限倍率，不解毒或增加最大生命。

保留原版体力和随机顺序：核心体力小于50直接返回，不抽随机数或扣体力；通过体力门槛后，伤势超出新准入仍消费一次bounded(5)并扣2点体力，战斗完成另扣2点。疗效读取实际能力，距离单独按能力最多100分档。AI自救、求医及选人共用新准入；优先攻击医者时，能力比较也保留完整64位。

HP、内伤、体力和候选随机状态在全部检查成功后提交，同角色施救保持三项结果。计算失败不改战斗朝向、效果格或伤害值；动画及行动完成保留独立边界。菜单能力缓存、共同入口返回值、战斗飘字与结果文字均为64位，施救者选择框和医疗结果框按长数字展开；原文字、颜色、等待及消费顺序保持。

回合状态扣血

状态结算资格与先内伤后中毒的顺序沿用原版。内伤扣血使用实际hurt除20；中毒扣血使用已定回合毒伤，按最大生命计算，并允许HP降至0。内伤上限、行动值中的伤势折算和医疗疗效分别读取各自正式公式，不能把行动值的比例折算套到武功增伤上。

AI统计与比较

AI入口按参战槽顺序、先攻击后当前HP累计双方总值；死亡和隐藏槽仍计入，人数保持有限槽位计数。总值以受检signed64保存，在呈现和等待前冻结，并传给攻势与后续移动计划；回退现场只重读当前行动者攻击，不重新累计队友。

攻势选择对行动者HP加攻击、敌方总值倍增、候选最大HP减当前HP、用毒减攻击以及队伍暗器的三倍攻击逐步检查溢出。医疗缺口和目标攻击比较保留64位，严格比较及同值早槽不变。队伍暗器仅在遇到负HP或正毒物品时计算三倍攻击后除2；随身暗器仍比较原攻击。选择失败不提交随机副本或选择字段，正常分支保留原随机顺序。

用毒、医疗和解毒超距回退使用受检的2×当前攻击，与先受检2×冻结己方总值、再除人数的结果比较；人数非正或乘法溢出时拒绝本次回退。最强目标的0初值、最弱目标的1000初值、无武功时最低内力需求1000等原分支保持；本次仅替换数值宽度与回绕。计划失败不代表整次AI动作回滚，此前已完成的移动或目标选择仍属于各自边界。

战斗休息恢复

沿用原版休息顺序：行动值等于角色基础speed／10时，体力增加bounded(3)+3，否则增加bounded(3)+2；受检加算后最高100。新体力小于30时不恢复生命或内力，也不调用后两处随机数；达到30时固定bound=新体力／10−2，先生命后内力，各增加bounded(bound)+3，再分别限制到角色实际最大值。bound为1时保留调用，随机状态不推进。

体力、当前HP／MP及最大值不能为负；所有加算使用受检signed64，取消word回绕。当前值高于最大值时仍在恢复加算后限制到最大值。三项结果全部成功才写参战角色、行动完成标记和随机状态；任一步溢出或非法输入都保留这三类状态。玩家与AI共用本路径，独立敌方休息不写回同ID的我方记录。

战斗状态面板的大数显示
