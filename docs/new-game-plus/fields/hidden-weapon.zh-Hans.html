字段 hidden_weapon

字段定义

hidden_weapon：暗器技巧。取值来源：通关TOML中的角色实际值；未入队角色读取当前RANGER基线。

项目规则与说明
下一周目值完整继承实际暗器技巧，不按周目夹值。
原版正常上限100；原版升级与秘笈修炼封顶100。不据此否定原版个别写入路径的越界值。依据：升级证据、修炼证据。
NG+数值暗器技巧增长与跨周继承均不设逐周目硬上限；不将原版100或旧方案的增长节点用作夹值。
既有CFG与默认样例hidden_weapon_cap_step默认100；旧方案以100 + (n − 1) × hidden_weapon_cap_step计算NG1／NG2／NG3的100／200／300。现在这些数值只作历史配置对照，不限制技巧实际值。
写入路径NG+的继承、升级与秘笈修炼保留原有增长量，不按周目封顶；溢出仍依64位存储合同拒绝。

4.4 玩家投掷带毒暗器时技巧项的全周目改号规则（已确认）

这是相对原版玩家投掷机器减号 的明确新规则，从NG1起适用于所有周目。

定位到src/battle/battle_setup.cpp原有if (item_poison > 0)分支： 只把item_poison - actor.hidden_weapon中的暗器技巧前减号改成加号，

即V − W改成V + W；此条件来自原代码，不是另加的“正毒”规则。

减目标抗毒的减号及其他步骤不变。原版汇编事实见 物品毒值字段页； 不能把本节新规则反称为原版行为或笔误修复。

普通物品的暗器技巧项不随玩家投掷改号；两条正毒路径都只比较实际毒力与目标实际抗毒，不再读取抗毒周目上限。玩家与AI投掷V≤0时保留各自公式和随机顺序；AI正毒投掷按统一上毒规则结算。

V = item.add_poison > 0，W = actor.hidden_weapon，A = target.anti_poison
x = trunc((V + W) / 2) − A  # 原版机器在W前是减号；全周目均改为加号
# x > 0 才可能中毒；之后按中毒章“上毒”结算，毒力 = trunc((V + W) / 2)，除数2
# x、Δ与后续中毒状态结算一律使用检查溢出的signed 64位逻辑数值

保留第一次除以2、减目标实际抗毒、非正中间值归零及最后再次除以2的顺序；不是V + trunc(W/2) − A。x>0只保证通过抗毒比较，若x=1则末次除以2后的理论增量仍为0；抗毒能力不按周目封顶，见抗毒章。

暗器技巧W读取当前角色64位值，不按周目夹值。

例：V=80、W=100、A=0、原有中毒0时，原版机器理论增量0，新规则毒力90、最深99、理论每次45，写入45；A=100时x=-10，理论增量0。

各周目使用同一64位加号公式，不在运行期保留原版16位回绕；是否产生正毒只比较x，结算见中毒章“上毒”。

只有保存到Legacy时才验证待编码角色数值的16位范围；新TOML保留合法64位值。
