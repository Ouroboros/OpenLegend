内伤

字段与上限

hurt为当前内伤；320名原版角色初值均为0。所有周目的正常范围固定为0～99，与原版NG1相同，不随周目增长；换周目清0。旧设计的hurt_cap_step已取消。

HurtMax = 99   # 内伤上限，所有周目相同
B = 100        # 伤势百分比判定的分母
H：角色当前实际内伤，0～99。
M：施救者当前非负医疗能力。
T：医疗公式的保底前治疗量。
伤势比例：H / B，比较前不取整。
p：待比较的百分数，例如50表示50%。
容量：目标当前最大生命与最大内力之和。
原路径除数：原版该路径把伤害折成内伤时的除数。

内伤与中毒采用同一种做法：数值范围固定，按原版量程判断伤势轻重；最大生命和最大内力决定受伤后内伤增加多快，最大生命决定内伤每轮造成的生命损失。百分比门槛用B，医疗疗效用HurtMax，两者不可互换。

新增内伤

容量 = target.maximum_hp + target.maximum_mp
新增内伤 = trunc(99 × 10 × 伤害 / (原路径除数 × 2 × 容量))
target.hurt = min(target.hurt + 新增内伤, 99)

原路径除数沿用原版：武功产伤与普通物品负回血为10，玩家／AI投掷为4。武功每次新增trunc(99 × 伤害 / (2 × 容量))；同样伤害下，投掷产生的内伤是武功的2.5倍。从零内伤起，累计约2倍容量的武功伤害才会满伤，逐次取整会使所需伤害略多。最大内力越高，同样伤害产生的内伤越少。

伤害取各路径原版用于产伤的值：武功为目标HP触底截断前的计算伤害；普通物品负回血与投掷为夹到0～最大生命之前的HP变化量绝对值。容量取目标本次结算时的实际最大生命与最大内力，敌方为周目成长后的值；容量为0时，正伤害直接满伤。实现按精确整数计算，不因中间量超出signed64而拒绝。

减少内伤的路径保持原算式：普通物品正回血减少trunc(add_hp / 4)，投掷正HP变化减少trunc(HP变化 / 4)；医疗、剧情休息、试炼轮间、升级及换周目清伤另按各自规则。

内伤造成的生命损失

内伤生命损失(角色) = trunc(角色最大生命 × 角色H / 2000)
每轮内伤扣HP = 内伤生命损失(本角色)
武功对伤者的增伤 = 内伤生命损失(目标)

满伤99时约为最大生命的4.95%，与满毒每轮约10%对应原版H / 20与中毒量 / 10的关系。低生命角色因取整较少：最大生命29、满伤时每轮扣1；最大生命不超过20时满伤也不扣血。实现按精确整数计算，不因中间乘积超出signed64而拒绝。

伤势门槛与各入口

内伤上限固定为99、比例分母为100，因此以伤势比例为输入的门槛、行动值惩罚和物品折算与原版NG1相同；改变的只有新增内伤与生命损失两类算式。地图移动计数、中毒条件与医疗准入各用自身规则。逐项实现与验证状态见实现清单。

伤势比例 = H / B          # B = 100；只用于比较，不先取整
内伤高于 p%：100 × H > p × B；低于 p%：100 × H < p × B
战场行动值 = max(trunc(有效速度 / 15) − trunc(100 × H / (40 × B)), 0)
普通物品内伤折算项 = trunc(50 × H / B)

严格大于／小于及H=0的原版特例分别保留；等于门槛时“高于”与“低于”都不成立。B=100时，以上各式分别等于原版的H > p、H < p、trunc(H / 40)与trunc(H / 2)。

原版机器边界与数值对照

原版世界地图每50次移动尝试（包括受阻与入场景）扫描队伍：内伤H>50或误用队伍槽号索引的中毒>50触发三项减1；剧情脚本opcode 12需H<33、中毒0且处于连续队伍前缀；试炼轮间只在前四组、主角H<50且中毒0时恢复。NG+只改变这些入口的内伤门槛。

原版菜单H>M＋20不能回血或治伤，H>75的基础回血约为trunc(M / 2)，失败时的核心体力结算另按原版；物品正／负回血均读取trunc(H / 2)，队伍医疗选择与人物状态页的生命分色为≤33／34～66／≥67；行动值为max(trunc(有效速度 / 15)−trunc(H / 40),0)。这些固定阈值不直接当成NG+疗效。

原版武功以目标trunc(H / 20)增伤，在目标HP触底截断前按trunc(计算伤害 / 10)产伤、封顶99；回合先按内伤再按中毒扣HP。投掷原版H=0／1～33／34～66／>66对应add_hp的/4／/3／/2／/1（add_hp=0则本项不变）；玩家投掷按H−trunc(HP变化 / 4)后夹99，AI沿自身路径写回。敌方AI原版自身H>50、队友H>40触发对应分支，旧医疗候选筛选另有M>目标H−30。

旧设计曾以99 + (n − 1) × hurt_cap_step逐周目提高内伤上限，并保留按绝对点数产伤和扣血：数值成长后，高生命角色一次受击即可满伤，满伤扣血却只有数点；低生命角色要承受数十次满血伤害才会满伤。该方案已取消，改为本页按容量产伤、按最大生命扣血的规则。

历史AI医疗候选筛选M>目标H−30不是NG+医疗成功条件，执行仍须满足医疗准入。玩家与AI投掷的伤害算式不合并。升级清伤、战后清伤的机器依据仍独立。

医疗

角色医疗补HP并治内伤，不解毒或提高HP上限。

H：目标治疗前的实际内伤。
M：施救者当前非负医疗能力。
Hmax：内伤上限HurtMax，固定为99。
s：实际内伤与Hmax之比。
f(s)：随伤势比例变化的疗效倍率。
R：同一次治疗抽取的整数0～4。
T：倍率计算出的治疗量，未应用10%保底。
Q：回血与治内伤共用的治疗量，已应用10%保底。

使用条件

战斗菜单要求体力>50、医疗能力≥20；医疗核心要求体力≥50，非战斗只调用核心。 原版核心消耗2点体力，战斗行动完成段另消耗2点。

距离＝trunc(min(max(M, 0), 100) / 15) + 1，最大7。距离分档固定读取100，不限制NG+实际医疗能力；不按周目能力上限夹值。

成功条件

H ≤ M + max(20, trunc(M / 5))

等于门槛可治，各周目共用。

失败条件

核心体力不足或H超出门槛：加HP和治内伤均为0。体力不足按原版直接返回，不消费随机数或核心体力；通过体力门槛后，内伤超出医疗准入仍抽取一次随机0～4并消耗核心2点体力。

医疗公式

NG1起各周目统一使用本式，Hmax固定为99。

s = H / Hmax                       # 0 ≤ H ≤ Hmax
倍率 f(s) = 80% − [(80% − 10%) / 2] × s² × (1 + s)
T = trunc(M × f(s)) + R
Q = max(T, ceil(M / 10))               # 回HP和治内伤共用10%保底
实际加HP＝min(max(目标HP上限−目标当前HP, 0), Q)
实际消除内伤＝min(H, Q)
治疗后内伤＝H−实际消除内伤

基础治疗量按整数分式精确取整，能力值不先转成浮点；比例系数以16位数位和signed64分片运算，完整保留分子／分母再除法。新增19位能力病例已通过Linux／Sanitizer的五项关联验证，失败时随机候选仍不提交；详见实现清单。

实现按等价整数分式取整：trunc(M × (16×Hmax³ − 7×H²×Hmax − 7×H³) / (20×Hmax³))。计算使用有界整数数位保留分式精度，避免19位能力转浮点后改变取整结果；随机值与10%保底仍按原公式应用。

两项共用Q；HP满仍可治内伤。分母用Hmax=99， 不用B=100。菜单、玩家和AI已接入共享疗效与64位返回通道，验证状态见实现清单。

实际世界菜单验证在已启动会话中设置NG+来源、周目与能力，再用公开按键完成施救者、目标选择及结果呈现。既有NG1／NG2八组病例继续核对疗效、满血治伤、体力与随机状态；新增NG999病例以医疗能力和HP上限7000000000000000000、当前HP及内伤0计算出5600000000000000003点回血，结果通道、完整19位字形和阴影均通过检查。此固定执行夹具未经过自然成长；完整游玩与平衡仍待验收。
