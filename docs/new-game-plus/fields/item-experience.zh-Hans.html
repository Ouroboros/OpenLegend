字段 item_experience

字段定义

item_experience：秘笈修炼经验。取值来源：换周目规则直接赋值。

字段中文名称下一周目值边界与说明
item_experience 秘笈修炼经验 0 清空当前秘笈修炼经验。

2.1 秘笈修炼规则

Pr = 原版秘笈修炼奖励比例规则
A0 = 原版资质费用基础系数
IqStep = 原版资质分档宽度
M0 = 原始武功等级上限

本场秘笈修炼经验 T = floor(实际人物战斗经验 X×Pr÷100)
资质系数 A(iq) = A0－floor(iq÷IqStep)
本周武功／隐藏阶级上限 Lcur(n) 由本周武功等级上限确定

程序读取角色本场实际人物经验、角色资质、原版修炼规则参数、原始武功上限和NG+等级步长后再计算。

原版当前Pr=80%、A0=7、IqStep=15、M0=10，默认martial_level_step=10； 这些数值用于说明和复算，不直接嵌入通用公式，也不另设秘笈周目倍率。本周等级上限的计算见武功熟练度字段定义。

2.1.1 有关联武功的秘笈：费用与熟练度

已学武功显示等级 = floor(对应武功槽熟练度÷100)＋1
Lfirst = 原版未学会武功参与费用计算时的起始显示等级
L = 已学武功显示等级；未学会时取Lfirst
C = need(i)×A(iq)×L
L≥Lcur(n)时不能继续完成

程序从当前秘笈物品定义读取need(i)，从角色读取资质与对应武功槽的熟练度。原版当前Lfirst=1；原始上限为10时，10→11使用系数10，之后依次使用11、12……。开放新等级上限不自动赠送等级、熟练度或永久效果。

经验与熟练度：item_experience是完成秘笈修炼的累计进度，不按比例转换成熟练度。战斗使用和秘笈成功写入同一武功槽熟练度，不是两份独立数值。

原版正常域，每次攻击结算：本槽熟练度 ← min(999, 本槽熟练度＋k)，k∈{1,2}
战后秘笈达标，已学同ID且该槽熟练度＜899：本槽熟练度 ← 本槽熟练度＋100

原版写入顺序：先逐次结算战斗攻击；战后若达到本档修炼费用，先提交秘笈属性效果并清零修炼经验，再按上式逐槽处理已学的同ID武功。首次学会则只向空槽写入武功ID，保留该槽原有熟练度，不额外加100。原版机器依据见攻击结算核查与秘笈修炼核查。

NG+设计沿用攻击结算每次1或2点、秘笈成功提升熟练度的原始增量，不按周目放大；本周允许提升的等级与边界按武功熟练度字段定义判断，不把原版的999和899固定门槛照搬到更高等级。运行时代码尚未实现这项扩展。

无对应武功秘笈的成功次数与费用见无关联秘笈成功次数字段页。

2.1.3 统一结算顺序

I' = I＋T

若 I'＜C：保存 I'，本场不完成
若 I'≥C：本场完成一次，先执行秘笈属性效果并令 I=0，再处理关联武功槽（若有）
同一场战斗不得再次检查下一档

本场修炼经验先加进当前进度。不够就留下以后继续攒；够了就只成功一次，先应用秘笈属性并清零进度，再按上文处理关联武功的学习或升级。即使多出来很多经验，也不会同一场连升多级，多余部分仍然丢掉。

  1. 人物经验按存活和人数规则分配并乘人物周目倍率。
  2. 秘笈修炼经验按Pr取实际人物经验的比例；原版当前为80%。
  3. 累计经验不足下一档费用时保留。
  4. 达到费用时，本场最多完成一档。
  5. 执行一次原秘笈属性效果，当前item_experience清零，多余经验丢弃。
  6. 若关联武功，再按上文规则处理已有武功槽或首次学习。

不设置独立修炼周目倍率；旧方案的222%和Mn不使用。need_experience、magic_id和永久效果字段必须从当前物品定义读取，不能针对表中六本秘笈写死数值或效果。

2.2 秘笈练满场数

由于每完成一档都会清零，场数必须逐档计算，不能直接用总费用除以单场奖励。

以下计算用于n≥2且上一周已经达到阶级上限的角色：
Kstart(n) = Lcur(n－1)
Kend(n) = Lcur(n)－1
Ck = 物品i、角色iq和阶级k代入对应费用公式后的结果
Tw(n) = 战斗w代入人物与秘笈奖励公式后的单场秘笈经验

本周总修炼需求 S(i,n) = Σ Ck，k=Kstart(n)…Kend(n)
本周所需场数 F(i,w,n) = Σ ceil(Ck÷Tw(n))

注意：F通常不等于ceil(S÷Tw(n))

每个新增阶级都要单独攒够，完成后剩余经验会被清掉，所以逐档计算再求和；新增多少档读取martial_level_step，不是固定写成十档。

原版当前资产与默认配置下，战斗99单人领取时，NG2～NG5人物经验为675、1125、1575、2025，对应秘笈经验为540、900、1260、1620。
