# NG+实现任务清单

## 范围与依据

实现入口为[NG+主设计](../new-game-plus-design.zh-Hans.html)，包括其引用的全部正式字段页，以及[人物继承](support/data-and-inheritance.zh-Hans.html)、[库存合同](support/inventory.zh-Hans.html)和[持久化合同](support/persistence.zh-Hans.html)。公式以各正式页面为准，本清单不复制公式。

旧未跟踪评审稿不能补充实现规则；原版机器证据用于确认原版行为。尚未确定的规则单独登记，不在实现中自行决定。

当前游戏持有完整逻辑快照，角色以64位逻辑字段为权威值；世界地图、场景、战斗和UI接口已迁移到该类型。Legacy转换、NG+配置传入、新游戏数值与随机消耗已通过相关测试。既有结算仍含窄类型和回绕，完整数值合法域、历史事件、TOML存档及NG+成长和战斗规则仍需实现。

|---|---|---|---|---|
| 1 | 核对主设计及全部引用规则，登记实现位置、缺口和未决项 | 无 | 每项正式规则有对应任务；规则与历史出处分开核对 | 已完成范围与缺口登记，原版入口随任务逐项验证 |

每个阶段先实现、再验证。阶段满足独立验收条件后按仓库规则提交并推送；未完成的实现和失败的验证不标记完成。

## 阶段验证记录

- 共用64位加减乘除：已实现，溢出、除零及最小负数除以−1时返回失败，不先执行非法算术。
- 经统一BUILD完成Linux应用Debug编译；`openlegend.checked_arithmetic`和`openlegend.model`共2项CTest通过。
- BUILD新增`--test-regex`，阶段测试仍经平台包装器执行；选择不到任何测试时报错。
- 角色逻辑类型与Legacy逐字段转换：已实现64位角色数值、UTF-8姓名、曾入队和秘笈历史；Legacy输入按字段有符号／无符号扩宽，输出在编码前检查16位范围。当前RANGER的320个角色数值往返一致，历史按零初始化。
- 姓名解码：核对项目CP950源文件指纹及13,503个映射，补齐10个同字异码；全部别名和Legacy姓名的规范编码往返通过测试。
- 周目CFG：已接入统一配置读取；按实际CFG经检查地计算内伤上限、百分比分母和战斗经验倍率。配置类型、周目范围、非法派生量程和运算溢出通过专项验证，保存窗口配置后NG+参数保留。
- 角色与CFG阶段经统一BUILD完成Linux应用Debug编译；`openlegend.ngplus_configuration`、`openlegend.role_state`、`openlegend.checked_arithmetic`、`openlegend.model`和`openlegend.persistence`共5项CTest通过。
- 完整逻辑快照：保存全部角色、其他RANGER记录、完整S／D、CFG、周目和来源；导入失败保持旧状态。Legacy输出在写文件前拒绝不可表示角色值、NG+来源或启用配置。游戏接口已迁移到逻辑状态。
- 配置和新游戏：SDL启动拒绝非法NG+配置，并把配置传入游戏快照；新游戏随机属性与Legacy在4个种子下数值及随机消耗一致。64位HP计算溢出时保持角色和随机状态不变。
- 最新统一BUILD全套回归：Linux应用Debug编译成功，129项CTest中114通过、15失败；失败列表与此前15项历史基线一致。基础6项均通过，本次迁移新增失败已消除；全套仍未通过。
- 上述结果不证明全部结算已扩宽或全部NG+规则已实现；完整字段域、静态匹配及跨字段不变量仍需验证。
