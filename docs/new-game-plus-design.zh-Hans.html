1. 人物、物品与战斗经验

1.1 数据事实与术语

  • WAR.STA中的经验是整场战斗总经验，不是单个敌人的经验。
  • 战斗结束后先按原规则确定胜负、存活资格和人数，再得到每名角色的原始个人奖励e0。
  • 下文所有“战斗所需场数”均使用整场总经验且不做队伍分配；多人存活时，每人的实际经验还要先按原规则分配。
  • 原版当前数据中，战斗99由5名番僧组成、整场经验450且可以重复触发，因此用作低收益可重复战斗样本；程序仍按战斗定义读取。
  • 秘笈修炼经验指item_experience；它与战斗中使用武功获得的1／2点熟练度不是同一个系统。

1.2 人物数值继承

本节处理原版角色记录中已经存在的字段，并额外包含已经明确批准的unassociated_manual_success_counts[ItemCount]。除该字段外，其他NG+新增字段、装备物品自身记录、库存、队伍、剧情状态和其他系统设计不属于本节。

1.2.1 范围与通用公式

Prev(r,f) = 源通关存档中角色r的原版字段f
Base(r,f) = 当前原版RANGER角色定义中的字段f
Cap(f,n) = 字段f在第n周目的合法上限
EverJoined(r) = 角色r是否曾在任一周目实际加入过队伍
RoleId(r) = r                                  # 固定身份不变量
HeadId(r) = Base(r,head_id)                     # 固定头像定义

若存档中的角色ID与记录位置r不一致：拒绝转换
若存档中的head_id与当前原版角色定义不一致：拒绝转换

不参与继承且不受EverJoined范围限制的原版字段集合：
FreshFields = { sexual, taking_items[4], taking_counts[4] }
对于所有角色r和f∈FreshFields：
Next(r,f) = Base(r,f)

其中角色携带物的恢复必须逐角色读取当前原版数据：
Next(r,taking_items[0..3]) = Base(r,taking_items[0..3])
Next(r,taking_counts[0..3]) = Base(r,taking_counts[0..3])
不得硬编码任何角色ID、物品ID或数量
不得在NG+转换阶段调用、重放或模拟KDEF剧情脚本

对于FreshFields以外的字段，若 EverJoined(r)=false：
Next(r,f) = Prev(r,f)

对于FreshFields以外的字段，若 EverJoined(r)=true且字段采用直接继承：
Next(r,f) = clamp(Prev(r,f), Min(f), Cap(f,n))

对于FreshFields以外的字段，若 EverJoined(r)=true且字段恢复原版基线：
Next(r,f) = Base(r,f)

名称、资源引用和数组槽位不使用数值clamp；它们原样复制后执行合法性验证。

角色ID与头像ID都属于固定角色定义，不参与继承、重置或clamp；与记录位置或当前原版角色定义不一致时表示存档损坏。性别与角色原版携带物不受历史入队范围限制：所有角色进入新周目时都从当前原版角色定义恢复这些字段，不继承上一周目的变化。这样敌人重新取得原版战斗携带物，可入队角色也能按原流程在每个周目转交一次原版物品。除这些字段外，只有曾经真正加入过队伍的角色才执行下面的逐字段转换；其他角色记录保持上一周目的值。直接继承不是把数值补到新上限，而是先复制实际值，再防止非法越界。

1.2.3 转换顺序与示例

  1. 从当前原版RANGER.GRP读取角色基线与字段合法域。
  2. 判断角色是否属于“曾在任一周目实际加入过队伍”的名单。
  3. 所有角色先恢复FreshFields；对其他字段，不在名单中的角色保持源存档值，在名单中的角色按第1.2.2节逐字段处理。
  4. 先处理level、maximum_hp、maximum_mp等上限依赖字段，再恢复hp、mp和physical_power。
  5. 继承并验证每名适用角色的unassociated_manual_success_counts[ItemCount]；它不随当前practice_item清空。
  6. 最后验证全部ID、字符串、数组槽位和数值范围；失败时拒绝转换，不静默修复损坏存档。
数值示意（不是代码常量）：
上一周目 maximum_hp=845、hp=213 → 下一周目 maximum_hp=845、hp=845
上一周目 maximum_mp=620、mp=75  → 下一周目 maximum_mp=620、mp=620
上一周目 hurt=40、poison=25      → 下一周目 hurt=0、poison=0
任一角色上一周目 sexual发生变化 → 下一周目不继承，统一取Base(r,sexual)；主角原版数据结果为0（男）
任一角色上一周目携带槽已清空      → 下一周目taking_items/counts恢复为Base(r,f)
上一周目 attack=138              → 下一周目 clamp(138, Min(attack), Cap(attack,n))

角色已经练出的等级、上限和能力不会因为换周目消失；新周目也不会自动赠送任何新增上限。只有明确指定为恢复、清零或清空的原版字段会发生变化。

1.3 物品继承

物品继承只读取前一周目结束时的全局库存。角色的equipment[2]和practice_item及其关联状态不属于库存来源，继续按第1.2节清空；taking_items[4]与taking_counts[4]也不属于库存来源，但会按第1.2节为所有角色恢复原版基线。

Type(i) = 从当前RANGER.GRP物品定义读取的item_type
MoneyId = 当前规则集指定的金钱物品ID
PrevCount(i) = 前一周目全局库存中物品i的合法数量

Keep(i) = (Type(i)=3) 或 (Type(i)=4) 或 (i=MoneyId)

InheritedCount(i) = PrevCount(i)，若 Keep(i)=true
InheritedCount(i) = 0，若 Keep(i)=false

下一周目只从旧库存带入药品、暗器和金钱；其他旧库存物品全部丢弃。物品类型必须从当前物品定义读取，金钱则使用规则集指定的物品ID。库存继承步骤只复制旧库存已有数量，不增加数量、不按周目放大，也不会从角色装备、携带槽或修炼栏直接回收物品。角色携带槽另行恢复原版基线，之后只有在角色入队或敌方战斗消耗时才按原规则发生转移或减少。

  • Type 3药品全部继承，数量保持前一周目库存值。
  • Type 4暗器全部继承，数量保持前一周目库存值。
  • 金钱物品按MoneyId额外进入白名单；原版当前规则值为ID 174“银两”，其原版item_type为0。
  • 所有其他物品一律不继承，包括其他Type 0物品、Type 1装备和Type 2秘笈。
  • 转换前验证库存物品ID和数量；发现非法值时拒绝转换，不静默修复。保留条目按源库存槽位顺序写入，删除其他条目并清空剩余槽位。
  • 本节只定义从前一周目转入的库存；库存继承步骤本身不自动产生任何旧库存中不存在的物品。角色原版携带物属于角色基线恢复，不属于库存继承。
  • 恢复角色携带物时，从当前原版RANGER.GRP逐角色复制taking_items[4]与taking_counts[4]；不得硬编码角色、物品或数量，也不得为了恢复携带物而预先执行任何剧情脚本。
  • 剧情脚本对携带物的追加仍只在本周目正常运行到对应事件时发生。原版opcode 41等脚本效果不属于NG+转换输入，不能在开局提前重放。
  • 原版样本：胡斐的角色携带槽包含闯王军刀、胡家刀法、小还丹和人参；每个新周目从RANGER.GRP恢复后，首次按原剧情入队时会再次转入全局库存并清空携带槽。装备与秘笈虽然可在本周重新取得，但因Type 1与Type 2不在库存继承白名单，不会跨周目累积。

1.4 人物升级需求

原始等级与经验门槛从游戏定义读取；原版当前数据中的30级、52000、4350、4200和150只用于说明与核对，不是运行时代码常量。

L0 = 原始经验门槛表支持的最高等级
E0(L) = 原始门槛表中等级L的累计经验
Dlast = E0(L0)－E0(L0－1)                # 原始最后一级费用
Dprev = E0(L0－1)－E0(L0－2)            # 原始倒数第二级费用
Sbase = Dlast－Dprev                     # 原始末段每级增量

本周等级上限：
Lcap(n) = L0＋(n－1)×role_level_step

L≥L0时：
实际升级费用 D(L) = Dlast＋(L－L0＋1)×Sbase
累计门槛 E(L＋1) = E(L)＋D(L)

第n周目从起始等级练到上限的需求：
C(n) = Σ D(L)，L=Lcap(n－1)…Lcap(n)－1

程序先从原始门槛表拿到最后两级各自需要多少经验，再用它们的差值继续延伸后续等级。周目等级上限和每周新增等级数来自原始上限与CFG。下面的200250、335250等数字只是把默认门槛和默认每周增加30级代入公式后的结果；换游戏数据或等级步长时，程序必须重新计算。

原版当前数据核对值（仅用于说明，不得硬编码）：
L0=30，E0(30)=52000，Dlast=4350，Dprev=4200，Sbase=150
role_level_step=30

代入后才可化简为：
D(L)=150L
C(n)=135000n－69750，n≥2

1.5 战斗经验倍率

Bbase = 原版一周目百分比基准
B2 = battle_experience_ng2_percent
Bstep = battle_experience_later_step_percent

B(1) = Bbase
B(n) = B2＋(n－2)×Bstep，n≥2

人物战斗经验 X = floor(e0×B(n)÷100)

原版当前值与默认CFG：Bbase=100%、B2=150%、Bstep=100个百分点。代入后，n≥2时才可化简为B(n)=100n－50%。

2. 秘笈修炼

2.1 秘笈修炼规则

Pr = 原版秘笈修炼奖励比例规则
A0 = 原版资质费用基础系数
IqStep = 原版资质分档宽度
M0 = 原始武功等级上限

本场秘笈修炼经验 T = floor(实际人物战斗经验 X×Pr÷100)
资质系数 A(iq) = A0－floor(iq÷IqStep)
本周武功／隐藏阶级上限 Lcur(n) = M0＋(n－1)×martial_level_step

程序读取角色本场实际人物经验、角色资质、原版修炼规则参数、原始武功上限和NG+等级步长后再计算。原版当前Pr=80%、A0=7、IqStep=15、M0=10，默认martial_level_step=10；这些数值用于说明和复算，不直接嵌入通用公式，也不另设秘笈周目倍率。

2.1.2 无关联武功的秘笈

c = 按角色ID＋物品ID读取的隐藏成功次数，初始为0
H0 = 原版无关联武功秘笈首次费用阶级
H = c＋H0
C = need(i)×A(iq)×H
H≥Lcur(n)时不能继续完成
成功后 c = c＋1

无关联武功秘笈使用持久化隐藏阶级。程序从物品定义读取need(i)，从角色与物品组合读取c。原版当前H0=2，所以第一次用2、第二次用3、再下一次用4；换书或换周目都不能重置。

  • 第一次使用H0，成功后依次使用H0＋1、H0＋2……；原版当前值对应2、3、4、5……。
  • 隐藏次数按角色与物品ID分别保存。换书、丢失、重新取得、物品归属重置和跨周都不清零。
  • 隐藏阶级与武功等级使用同一Lcur(n)。原版当前H0=2、M0=10，所以NG1最多成功8次；后续每周新增档数读取martial_level_step，默认10档。
  • 永久属性每次成功只应用原物品字段一次，不随周目放大，并限制到对应玩家字段的本周上限。

2.1.3 统一结算顺序

I' = I＋T

若 I'＜C：保存 I'，本场不完成
若 I'≥C：本场完成一次，执行一次对应效果，然后令 I=0
同一场战斗不得再次检查下一档

本场修炼经验先加进当前进度。不够就留下以后继续攒；够了就只成功一次、执行一次升级或永久属性效果，然后把进度清零。即使多出来很多经验，也不会同一场连升多级，多余部分仍然丢掉。

  1. 人物经验按存活和人数规则分配并乘人物周目倍率。
  2. 秘笈修炼经验按Pr取实际人物经验的比例；原版当前为80%。
  3. 累计经验不足下一档费用时保留。
  4. 达到费用时，本场最多完成一档。
  5. 执行一次原学习／升级／永久属性效果。
  6. 当前item_experience清零，超过费用的部分丢弃。

不设置独立修炼周目倍率；旧方案的222%和Mn不使用。need_experience、magic_id和永久效果字段必须从当前物品定义读取，不能针对表中六本秘笈写死数值或效果。

2.2 秘笈练满场数

由于每完成一档都会清零，场数必须逐档计算，不能直接用总费用除以单场奖励。

以下计算用于n≥2且上一周已经达到阶级上限的角色：
Kstart(n) = Lcur(n－1)
Kend(n) = Lcur(n)－1
Ck = 物品i、角色iq和阶级k代入对应费用公式后的结果
Tw(n) = 战斗w代入人物与秘笈奖励公式后的单场秘笈经验

本周总修炼需求 S(i,n) = Σ Ck，k=Kstart(n)…Kend(n)
本周所需场数 F(i,w,n) = Σ ceil(Ck÷Tw(n))

注意：F通常不等于ceil(S÷Tw(n))

每个新增阶级都要单独攒够，完成后剩余经验会被清掉，所以逐档计算再求和；新增多少档读取martial_level_step，不是固定写成十档。原版当前资产与默认配置下，战斗99单人领取时，NG2～NG5人物经验为675、1125、1575、2025，对应秘笈经验为540、900、1260、1620。

3. 持久化与实现约束

3.1 隐藏次数与持久化

ItemCount = 当前物品定义数量
H0 = 原版无关联武功秘笈首次费用阶级
count[role_id][item_id] ∈ [0, Lcur(n)－H0]
item_id ∈ [0, ItemCount－1]
仅当 magic(item_id)=-1 且 need(item_id)>0 时允许count非0
NG+转换：role_id∈EverJoinedRoles时原样继承；其他角色保持源存档中的count

隐藏次数不是“当前装备这本书的临时值”，而是角色对每一本无关联秘笈各自的长期记录。角色把书丢掉、换成别的书、下一周目重新取得，原次数仍然存在，因此不能靠换书把费用刷回第一次。

  • 新增unassociated_manual_success_counts[ItemCount]，按角色保存、按物品ID索引；原版当前ItemCount=200。
  • 是否使用计数由当前物品定义中的magic_id与need_experience判断；其他位置必须为0。
  • EverJoinedRoles来自存档中的历代实际入队记录；其中角色的隐藏次数完整继承，其他角色保持源存档值。
  • practice_item和当前item_experience仍按周目转换规则清空，但历史成功次数不清空。
  • 隐藏次数最大为Lcur(n)－H0；原版当前参数与默认NG999配置下为9988。
  • 修炼经验累计值使用64位逻辑字段，不允许16位回绕。
  • 由于新增必需字段，NG+ TOML使用format_version=2、ruleset_version=3，不自动迁移旧格式。

3.2 边界与实现要求

Nmax = CFG允许的最大周目
Lmax = M0＋(Nmax－1)×martial_level_step
HcountMax = Lmax－H0
PaidTierMax = Lmax－1
Amax = max(A(iq))，iq取当前角色字段允许域
NeedAssocMax = max(need(i))，magic(i)≥0
NeedUnassocMax = max(need(i))，magic(i)=-1且need(i)>0
WARmax = max(WAR(w))，w取当前战斗定义
Bmax = B(Nmax)

关联武功单档最大费用 = NeedAssocMax×Amax×PaidTierMax
无关联武功单档最大费用 = NeedUnassocMax×Amax×PaidTierMax
最大整场人物战斗经验 = floor(WARmax×Bmax÷100)
最大单场秘笈修炼经验 = floor(最大整场人物战斗经验×Pr÷100)

  • NG1关联武功秘笈保持原行为；无关联武功第一次使用H0，原版当前值为2；成功后逐档涨价是明确的新规则。
